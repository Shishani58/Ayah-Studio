# task-files.md — правила task-файлов

Перед первой правкой кода для нетривиальной задачи создать
`docs/tasks/YYYY-MM-DD-короткий-слаг/task.md`.

**Нетривиально** = меняет пайплайн/логику генерации, формат БД, GUI-поведение,
больше одного файла, или баг-репорт с логами.

## Шаблон

```md
# <Цель>

## Скоуп
Что входит / что НЕ входит.

## Доки
- docs/project.md — прочитан / пропущен (почему)
- <другие доки и какое правило дали>

## Решения
Ключевые развилки и выбор.

## Чек-лист
- [ ] ...

## Проверка
Что и как проверено (тесты, метрика на эталоне, ручной e2e).

## Блокеры
Что осталось / пропущено и почему.

## Docs
Docs unchanged: … | Docs updated: [файлы]
```

Task-файл — запись решений, не транскрипт. Не логировать рутинные вызовы
инструментов, если они не объясняют решение/блокер/проверку.
