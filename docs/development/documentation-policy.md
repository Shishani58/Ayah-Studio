# documentation-policy.md — правила документирования

- Держать доки **пропорциональными**: обновлять релевантные при изменении
  поведения, пайплайна или формата данных. Не плодить доки впрок.
- `docs/project.md` — единственная точка входа в архитектуру/инварианты.
  Менять при изменении пайплайна, модулей или формата БД.
- `docs/STATUS.md` — прогресс по фазам; обновлять при завершении/появлении работы.
- Фичи-специфика → `docs/features/<feature>.md` (создавать по мере надобности).
- При завершении задачи в task-файле фиксировать `Docs unchanged: …` или
  `Docs updated: [файлы]`.
- README — лицо проекта для пользователей; держать двуязычным (RU+EN) и
  синхронным с реальными командами/возможностями.
