- **Черновая ручная разметка**: экран суры упрощён — отладочные VAD/TEN/DSP/log
  кнопки убраны. Добавлены «Поставить старт» (текущая позиция аудио → выбранный
  аят, `edited`), «Разметить по паузам» (energy/TEN/VAD внутри алгоритма,
  запись `auto`, `edited`/`verified` как якоря) и «Корректировка» (точный проход
  по `auto`, ручные/проверенные метки не трогает). Pause-backed черновые старты
  пишутся в `pause.center_ms`, не в `pause.end_ms`, чтобы старт ревью не попадал
  резко на атаку следующей фразы. В панели волны есть read-only overlay «паузы»:
  показывает accepted/`weak-dsp`/rejected решения pause pipeline; под волной
  открывается таблица видимых pause-кандидатов с длительностью, причиной решения
  и DSP/VAD метриками, клик по строке переносит плеер в центр паузы.
- **UI ревью**: верхняя панель разделена на навигацию, плеер и действия с сурой;
  статус расчёта/ошибки больше не ломает строку кнопок. Проверено без
  горизонтального переполнения на 1280, 1100 и 820 px.
- **Режимы генерации**: `full` — точный полный forced alignment; `fast` —
  экспериментальный быстрый режим (паузы → онсет + растущее NN-окно). Старый
  `hybrid` оставлен в API для совместимости, но не показывается в UI.
- **Перепроверка (recheck)**: кнопка «🔍 Перепроверить» в ревью — аудит уже
  готовых тайм-кодов без перегенерации и без записи в БД (`core/recheck.py`,
  `GET /api/sura/{n}/recheck`). Для каждого аята с временем — greedy-decode аудио
  в этой точке и сравнение услышанного с ожидаемым началом аята и началами
  соседей (±2). Вердикт **чисто относительный**: если начало соседнего аята
  совпадает лучше своего (на маржу 0.10) → `shift` «звучит как аят N»
  (подсветка строки и маркера красным, бейдж `→N`); иначе `ok`. Абсолютный порог
  намеренно НЕ используется: на мураттале sim корректных аятов 0.14–0.78,
  неразделим (калибровка на эталоне Шатри: абсолютный фолбэк фолзил ~45%
  корректных аятов, относительный — 0 ложных, ловил off-by-one 30/40, дрейф
  +4/+8 с и локальный сдвиг точечно). Повторяющиеся рефрены акустически
  одинаковы → `ok` даже при сдвиге (предел метода, правится на слух).

## Быстрый режим — доведён до критериев приёмки (вровень с full, ~1.8× на длинных)

`mode='fast'` подключён в pipeline/UI; после фиксов 2026-06-27 (акустический DP +
кэш эмиссий + wasl-прогон + фолбэк коротких сур, см. ниже и task-файл) даёт

интро-басмали` (`1` — басмала это аят 1; `9` — басмалы нет), но теперь имеет

не-power-of-two сегменты паузы; отладочные overlay-кнопки убраны с экрана суры.

## Длинные суры — тайловый режим (tiled)

`mode='tiled'` (`core/align_tiled.py`) — для очень длинных сур, где **full**
упирается в память, а **fast** дрейфит. Корень проблемы full: Viterbi
`_ctc.forced_align` держит матрицу обратных указателей `T×(2L+1)`; на Бакъаре
(T≈354k кадров, L≈47k токенов) это около **246,5 ГиБ** → своп-трэшинг (растёт как
длина²). Fast не спасает: паузы на длинных васл-сурах перестают быть якорями →
дрейф → фолбэк в full → снова сотни гигабайт.

Решение — тайлинг ТОЧНОГО forced-align: известный текст режется на куски по
бюджету токенов/времени, каждый кусок выравнивается точным Viterbi в узком окне.
Якорь — не пауза, а **точно найденная граница предыдущего куска** + измеренный
темп (на уровне куска приора с запасом хватает). Окно кончается у начала
следующего аята (иначе forced-align тянет хвост куска вперёд), 3 аята правого
контекста впитывают краевой дрейф (их онсеты отбрасываются), 2 — левого для
lead-in. Каждый кусок заново цепляется за реальный звук → ошибка не каскадит,
васл не нужен. Память на кусок ограничена (~сура-78) и освобождается.

Проверка (эталон Шатри): **паритет с full** — сура 112 = 0 мс; 78 (даже
принудительно в 9 кусков/8 швов) max **17 мс**, дрейф по швам не копится.
**Бакъара (286 аятов, 118 мин аудио) vs GT**: 54 куска, **20.4 мин** (было ~час),
точность медиана **77 мс** / p90 681 / p95 1124 / max 2154, ≤150=67% / ≤500=87%
(вровень с full, без дрейфа). Пик памяти ~1 ГБ (после ограничения роста окна;

считает emissions один раз на всю суру и режет их по chunk-окнам; для размеров
окон сначала берётся empirical prior из `data/references/*.db`, fallback — старый
text-unit prior. Скорость/точность после этого изменения не перебенчены. UI:
«точно · большие» в обоих списках режимов; oversized full теперь безопасно

## Надёжность FULL и FAST — 2026-10-13

Общий ONNX inference переведён на одно окно за вызов. FULL проверяет слабый
первый звук отдельно, исключает blank из confidence, сохраняет trace и
confidence, отклоняет неполные пути. Слабый префикс через подтверждённую паузу
