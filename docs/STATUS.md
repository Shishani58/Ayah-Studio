## Тест-проход (валидация на аудио Абубакра Шатри, есть ground truth)

Аудио: `~/Desktop/Abu_Bakr_Ash-Shatri/{078..114}.mp3`; эталон
`data/references/abu_bakr_ash_shatri.db`.

- **Точность выравнивания** — весь джуз Амма (37 сур / 564 аята, full vs эталон):
  после компенсации лага CTC (`ALIGN_LAG_MS=200`) **медиана 57 мс, p90 190 мс,
  p95 306 мс, ≤150 мс = 85%, ≤500 мс = 97%** (было до компенсации: медиана 231,
  p95 485). Цель (медиана <150 / p95 <500) перевыполнена. Время: ~167 с на джуз
  (4.5 с/сура). Остаток (~5% аятов, max ~1.2 с) — локальные «срывы» Витерби на
  повторах/распеве; правятся в ревью.
- **Систематический лаг CTC**: знаковая ошибка была +230 мс у 100% аятов (токен
  эмитится после онсета). Снимается константой `ALIGN_LAG_MS` (env-override) —
  свойство модели, не чтеца.
- **Silero VAD починен**: v5-экспорт требует 64 сэмпла контекста + 512 = 576 на

  корректные паузы, попадающие в границы аятов (8/9 на сурах 108+114). Снэп к
  паузам как улучшение пока не включён — выравнивание и так в цели (медиана
  57мс); межаятная привязка остаётся опцией для остаточных ~5% «срывов».
- **Запуск проверен (macOS)**: `surah-cutter --help`, CLI-батч (генерит валидную

  добавлены недостающие `pyarrow`/`huggingface-hub`, extra `oracle`→`align`
  (алиас сохранён), из core убраны неиспользуемые `librosa`/`ctc-segmentation`.

## Фаза 3 — ONNX-рантайм (✅ готово, паритет подтверждён)

Лёгкий рантайм без torch — **бэкенд по умолчанию `onnx`** (`DEFAULT_BACKEND`,
env `SURAH_CUTTER_ALIGN_BACKEND`).

- **Экспорт int8**: `tools/export_onnx.py` → `models/wav2vec2-quran-phonetics.onnx`
  (122 МБ int8; fp32 377 МБ — dev-артефакт). Рецепт: легаси torch-экспортёр
  (`dynamo=False` — новый dynamo-граф `view_*/val_*` ломает квантайзер),
  `quant_pre_process(skip_symbolic_shape=True)` (symbolic shape падает на Range),
  `quantize_dynamic` только по `MatMul`. Sidecar: `.onnx.vocab.json` (40 токенов),
  `.onnx.meta.json` (`do_normalize`).
- **Витерби вендорен**: `core/_ctc.py` (чистый numpy) — бит-в-бит совпадает с
  `ctc_forced_aligner.forced_align` (проверено, `max_start_diff=0`). Снимает
  зависимость от librosa/numba/scipy.
- **Паритет точности onnx vs torch** на джузе Амма (564 аята): **медиана 59 мс,
  p95 310 мс, ≤150 = 86%, ≤500 = 97%** — идентично torch (57/306). Скорость
  full-align ~435 с/джуз (~2.6× torch; гибрид-режим ф.4 ускорит, гоняя нейронку
  только на трудных окнах).
- **Генерация без тяжёлых модулей**: проверено — `pipeline.process_surah` не
  импортирует torch/transformers/librosa/pyarrow (всё в `align` extra, только для
  ре-экспорта/оракула). Транслитерация — из вендоренного `data/word_tr_cache.json`.

## Фаза 5 — Web-GUI (✅ дашборд + ревью)

Лёгкий web-GUI вместо Qt: pywebview (системный WebView, без Chromium) + FastAPI/
uvicorn (локальный сервер: JSON-API + SSE-прогресс + раздача аудио/статики) +
vanilla HTML/JS. ~10 МБ deps против Qt 1.2 ГБ. Модуль `surah_cutter/webgui/`,
entry `surah-cutter-gui` → `webgui.launch:main` (фоллбэк — браузер).

- **Дашборд**: сетка 114 сур со статусами (not-processed/processed/verified),
  индикатор наличия аудио, открытие проекта (папка + .db), выбор режима
  full/fast (`full` по умолчанию).
- **Явная генерация**: панель с прогресс-баром, текущей сурой, временем старта,
  живым таймером прошедшего и кнопкой отмены (`/api/generate/cancel` — стоп после
  текущей суры; события `sura_start`/`cancelled`). Подтверждение перед запуском.
- **Возобновление**: основная кнопка генерирует только недостающие суры
  (`only_missing` → `_processed_suras()` по наличию timings; генерация по-суре
  атомарна, так что прерванный/упавший прогон продолжается после перезапуска —
  «▶ Продолжить · осталось K»); отдельная «↻ Заново всё» для полной перегенерации.
- **Память состояния**: `webgui/settings.py` (`~/.surah-cutter/settings.json`) —
  последняя папка/БД/режим. При старте `_restore_from_settings()` авто-открывает
  проект (пути проверяются на существование), сохраняется при открытии и смене
  режима (`/api/settings`).
- **Пер-сура генерация**: в экране ревью — «Пересчитать суру»
  (`/api/generate {suras:[n], mode}`), статус с таймером, авто-перезагрузка
  тайм-кодов. Перегенерация не трогает `edited`/`verified`; пересчитываются
  только отсутствующие/`auto`. Несгенерированная сура открывается с кнопкой
  «Рассчитать».
- **Режимы генерации**: `full` — точный полный forced alignment; `fast` —
  экспериментальный быстрый режим (паузы → онсет + растущее NN-окно). Старый
  `hybrid` оставлен в API для совместимости, но не показывается в UI.

## Быстрый режим — исследовательский, результат пока неудовлетворительный

`mode='fast'` подключён в pipeline/UI, но **не готов как режим ускорения**.
Текущий UI нужен в первую очередь для диагностики фаз.

Что сделано:
- фаза пауз: `ENERGY → DSP(flatness/ZCR/rms) → локальный TEN/Silero для первой
  интро-басмали` (`1` — басмала это аят 1; `9` — басмалы нет);
- отдельные overlay-кнопки в суре: `фаза 1` (energy), `DSP`, `фаза 1 итог`,
  `TEN`, `VAD`;
- `TEN`/`VAD` считаются по видимому диапазону, разными цветами;
- кнопка `лог` запускает fast trace и показывает: сколько пауз найдено/отклонено,
  DSP/VAD причины, какие слова читались моделью, onset/conf/delta, связь
  `pause/wasl/interp` по аятам, суммарные секунды нейро-чтения.

Обновление 2026-06-27 — **главная поломка исправлена** (off-by-one на распевных
сурах). Корень был в Phase 1c: DP сопоставлял паузы к аятам по смещённому
char-приору (распев растягивает аяты неравномерно → приор уезжал до ~3с → DP
съезжал на одну паузу при наличии лишних вдохов). Заменено на **акустическую
стоимость**: для каждой паузы greedy-CTC-декод окна `[p-50,p+2500]мс` сравнивается
с началом аята (первые 4 слова); стоимость идёт в тот же DP. Порядок DP различает
аяты с одинаковым началом (98: «inna lladhīna kafarū/āmanū»). На джузе Амма
(564 аята): fast med **58мс** / p95 **576** / ≤500 **95%** — почти вровень с full
(59/310/97%), без регрессий (sura 87: med 78→40, ≤150 68%→100%).

Остаток до production: (1) скорость **1.43×** ниже цели 1.5× — декод-проход
добавил coverage, чинится переиспользованием эмиссий для refine; (2) p95 чуть выше
~500 из-за крошечных повторяющихся сур (113/103/105) — кандидат на фолбэк к full.
До этого `full` остаётся режимом по умолчанию.
- **Ревью**: HTML5-плеер (play/pause, скорость, луп аята), canvas-волна по пикам

- **Проверено headless** (curl, аудио Шатри): открытие проекта (37 сур найдено),
