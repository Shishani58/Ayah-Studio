## Быстрый режим — доведён до критериев приёмки (вровень с full, ~1.8× на длинных)

`mode='fast'` подключён в pipeline/UI; после фиксов 2026-06-27 (акустический DP +
кэш эмиссий + wasl-прогон + фолбэк коротких сур, см. ниже и task-файл) даёт
точность вровень с full при ~1.8× ускорении на длинных сурах. Внутри fast фаза
пауз остаётся `ENERGY → DSP(flatness/ZCR/rms) → локальный TEN/Silero для первой
интро-басмали` (`1` — басмала это аят 1; `9` — басмалы нет), но теперь имеет
второй weak-pass для коротких/слабоконтрастных пауз (`weak-dsp` в fast-log);
края принятых пауз уточняются по несглаженному RMS, чтобы `pause.end_ms` не
уезжал вправо из-за smoothing; DSP flatness корректно обрабатывает короткие
не-power-of-two сегменты паузы; отладочные overlay-кнопки убраны с экрана суры.

Обновление 2026-06-27 — **режим доведён до критериев приёмки.** Главная поломка
(off-by-one на распеве) была в Phase 1c: DP сопоставлял паузы к аятам по смещённому
char-приору. Заменено на **акустическую стоимость** (greedy-CTC-декод окна после
паузы сравнивается с началом аята, 4 слова), плюс три доводки: кэш эмиссий
(refine переиспользует декод-окно), wasl-прогон одним непрерывным окном, и фолбэк
коротких сур (<60с) на full. Все фиксы — из чтения лога `model_reads`.

Обновление 2026-06-28: основной fast-match переведён с глобального выбора на
последовательное подтверждение пауз. Алгоритм идёт по ожидаемым аятам, коротко
читает звук после паузы, принимает паузу только если она звучит как текущий аят;
если слышен будущий аят — сначала ищет пропущенный участок на ранних/слабых
паузах, иначе отдаёт его в локальный wasl-align. В trace добавлен `pause_budget`
(границы аятов, waqf-знаки, принятые/использованные/прочитанные паузы),
`pause_sequence_events`, `n_refine_skipped`; сильные pause-backed совпадения
берут старт по центру паузы без дополнительного refine, а greedy-чтение для
подтверждения начинается строго от начала паузы.
Обновление 2026-06-29: слабые, но сопоставленные pause-backed границы тоже
остаются на центре паузы, если локальный refine нашёл первое слово рядом с этой
паузой. Refine в таком случае подтверждает достоверность паузы, но не
перетаскивает старт на onset слова после неё.
Дополнение 2026-06-29: recovery больше не берёт паузу для текущего аята, если
глобальное наблюдение этой паузы сильнее указывает на другой аят. Если же
observed указывает на текущий аят, recovery может использовать такую раннюю
паузу даже при жёстком prior/prefix reject. На суре 11 Badr Turki аят 13 ушёл с
поздней паузы 244.67s на раннюю паузу 234.64s; поздняя пауза логируется как
`skip_recovery_observed_mismatch`.
Для коротких `weak-dsp` пауз добавлен prefix-guard против хвоста предыдущего
аята, а repair теперь не уводит wasl-старт от сильной видимой паузы. Проверка на
Бадре Турки, сура 77: слабая пауза 10 стала `extra`, аяты 10/11 встали на паузы
11/12, аят 26 остался на центре паузы 89.76s; `drift_detected=False`,
pause_coverage 0.939.

Добавлен локальный wave/tempo prior. Между соседними паузами считается длина
звучащих участков (`prev_speech_ms`, `next_speech_ms`) и сравнивается с
текстовой длительностью соседних аятов (`_unit_len`: буквы + долгие гласные) по
локальному `tempo_ms_per_unit`; waqf-знаки из mushaf-текста попадают в trace как
`waqf_before/after`. Prior используется мягко: добавляет небольшой `tempo_score`
к последовательному выбору, помогает recovery при `future_gap`, а для коротких
`weak-dsp` пауз с плохой акустикой и плохим span-ratio даёт `tempo_mismatch`.
Greedy-чтение после паузы остаётся главным подтверждением. Fast-log теперь
показывает `tempo`, `span_prev`, `span_next`, `waqf`; на Бадре Турки, сура 77,
таймкоды не изменились, `drift_detected=False`, а у аята 26 длина волны
подтверждает пропущенный участок (`tempo_score=0.065`).
Следом добавлен micro-pause scan для незаметных пауз: если первый sequential pass
видит `future_gap`, для каждого пропущенного аята вычисляется ожидаемая точка
между предыдущим и будущим якорем по текстовым единицам, затем вокруг неё ищется
локальная RMS-просадка внутри speech-span. Если рядом нет уже найденной паузы,
просадка добавляется как synthetic accepted pause с reason `micro-tempo`, после
чего sequential matching запускается заново и читает её обычным greedy-decode.
Если просадка рядом с существующей паузой, она только логируется как
`near_existing`, чтобы не плодить дубли. На суре 77 для аята 26 micro-scan нашёл
долину рядом с уже существующей сильной паузой 89.76s (`near_existing`), поэтому
результат остался стабильным.

Обновление 2026-09-01: последовательный FAST использует явные
`TextDisambiguation`, `TempoObservation`/`TempoEstimate` и `PauseReadPlan`.
Одинаковое короткое начало больше не считается доказательством: окно включает
первое различающее слово и при слабом чтении расширяется ступенчато. Локальная
скорость учится только на надёжно закрытых интервалах, прогнозирует широкий
pause-corridor и влияет лишь на порядок/длину чтения. Wasl читается атомарным
блоком от начала левой pause-owner до конца правой; внутри блока старты берутся
из CTC. Trace содержит темп, разброс, pause-corridor, текстовых конкурентов,
план окна и явные координаты owner/marker/decode-start.
Hard-set Abu Bakr Ash-Shatri 78/80/83/87/89/98: 175 границ, aggregate

## Длинные суры — тайловый режим (tiled)

`mode='tiled'` (`core/align_tiled.py`) — для очень длинных сур, где **full**
упирается в память, а **fast** дрейфит. Корень проблемы full: Viterbi
`_ctc.forced_align` держит матрицу обратных указателей `T×(2L+1)`; на Бакъаре
(T≈354k кадров, L≈47k токенов) это около **246,5 ГиБ** → своп-трэшинг (растёт как
длина²). Fast не спасает: паузы на длинных васл-сурах перестают быть якорями →
дрейф → фолбэк в full → снова сотни гигабайт.

Решение — тайлинг ТОЧНОГО forced-align: известный текст режется на куски по
бюджету токенов/времени, каждый кусок выравнивается точным Viterbi в узком окне.
Якорь — не пауза, а **точно найденная граница предыдущего куска** + измеренный
темп (на уровне куска приора с запасом хватает). Окно кончается у начала
следующего аята (иначе forced-align тянет хвост куска вперёд), 3 аята правого
контекста впитывают краевой дрейф (их онсеты отбрасываются), 2 — левого для
lead-in. Каждый кусок заново цепляется за реальный звук → ошибка не каскадит,
васл не нужен. Память на кусок ограничена (~сура-78) и освобождается.

Проверка (эталон Шатри): **паритет с full** — сура 112 = 0 мс; 78 (даже
принудительно в 9 кусков/8 швов) max **17 мс**, дрейф по швам не копится.
