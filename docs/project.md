# project.md — архитектура и инварианты

Точка входа в документацию. Читать перед изменением архитектуры, пайплайна или
формата БД.

## Цель

Из папки аудио (один файл = одна сура, имена `001…114`) построить SQLite с
тайм-кодом **начала** каждого аята и дать **визуально-слуховую** проверку и
правку результата. Приоритеты: скорость, точность, лёгкость.

## Ключевая идея

Текст Корана статичен и известен. Поэтому это **forced alignment** (раскладка
известного текста по времени), а не распознавание речи. Конец аята = начало
следующего; конец последнего = конец файла → ищем только **старт каждого аята**.

## Обязательный контракт FAST (2026-10-13)

FAST находит паузы и читает моделью сопоставления текста только небольшие
локальные участки, достаточные для определения нужного аята/границы.
Полное акустическое чтение суры, включая предварительный emissions-pass
и покрытие всей записи последовательными окнами, запрещено. Контекст
расширяется только для конкретной неоднозначности; неуверенные границы
перепроверяются локально или остаются для ревью. Скрытый переход в FULL/tiled
запрещён. Поиск пауз DSP/VAD допускается.

## Эксперимент единого FAST (2026-10-14)

`process_surah(..., mode="fast", experimental_fast=True)` и явный флаг
`tools.bench_fast_models --experimental` запускают `fast_executor` с акустическими
CTC/Tarteel адаптерами. Обычный GUI/CLI FAST пока использует прежние loops:
переключение и их удаление разрешены только после парных ворот качества M5.
Новый путь последовательно доказывает минимальные целые слова представления,
сверяет внутренние/соседние повторы, качество каждой различающей единицы и
геометрию паузы/onset. Произнесённые названия начальных букв сохраняют владельца
канонического слова; сильное противоречащее продолжение отклоняет partial proof.
В prospective v3 sparse anchor допускается из уже прочитанного глобально
различающего начала: пропущенный текст остаётся confidence=0/review, без
дополнительного scan. Physical lookahead расширений ограничен двумя аятами,
8 кандидатами и теми же 6s/65%/200%. Старые strict/M5 результаты не переобозначены.
Повторные аяты требуют отдельного left-tail у левого края DSP-паузы и right-opening
у правого края. Полный DSP interval хранится отдельно от короткого speech crop;
длинный затухающий речевой хвост не доказывает midpoint паузы. Cache32MiB хранит
posterior только до eviction; trace сохраняет scalar comparisons, не матрицы.
Confidence составного proof ограничен минимумом всех его essential units,
включая previous-tail из отдельного чтения.
Конечные расширения используют точные локальные fragments, независимые CTC
альтернативы или измеренный незавершённый speech edge. Подтверждение по posterior
сравнивает canonical rivals, null и unrestricted residual mass; forced path сам
по себе не является proof. ASR качество привязано к selected tokens каждой
доказательной единицы; некалиброванный attention timing остаётся выключенным.
Дополнительные первые гипотезы — отдельный VAD/RMS-поиск в15s после DSP onset;
исходный набор DSP-пауз и дополнительные интервалы/ID сохраняются отдельно.

Run key включает PCM/текст, модель/revision, adapter/algorithm/policy/lag/DSP,
VAD weights/runtime и фактический pause pool. Bundle фиксируется до decode.
Identity text runtime фиксирует реально загруженные weights/config/tokenizer,
vocab/blank/normalization/providers/versions. Implementation fingerprint берётся
из загруженного Python code/defaults, не изменившегося файла. Benchmark spy
консервативно меняет этот fingerprint: его ключ может отличаться от GUI/CLI
при тех же вычислениях, но не позволяет stale resume.
`auto` и `verified` — статусы сохранения, не акустическое доказательство.
Явный FAST resume не принимает старые/неизвестные ключи; до активации нового
пути Web/Qt консервативно пересчитывают auto FAST, полностью ручные суры пропускают.
[Исполнение, реальные измерения и ограничения](tasks/2026-10-14-fast-full-execution/report.md).
[Исправления второго ревью и новые измерения](tasks/2026-10-14-fast-review-fixes/report.md).

## Текущий пайплайн (на суру)

Пункты 4–6 описывают CTC-адаптер Quran Phonetics. Для Tarteel Tiny/Base действует
отдельный локальный адаптер, описанный ниже; общий запрет полного чтения тот же.

1. Декод → PCM 16 kHz mono (bundled ffmpeg).
2. В auto известный чтец и готовые тайминги → отдельный reference-путь.
   Явно выбранные FAST/FULL/tiled всегда выполняют выбранный алгоритм.
3. FAST сначала находит DSP/VAD-паузы. Акустическая модель текста пока не вызывается.
4. Читается локальное начало после intro-паузы (2.5 с; только при недостатке
   CTC-пути 4/6 с), без чтения всей басмалы. После кандидатов пауз читается
   начальная фраза (1.3 с речи плюс пауза). Различающие тексты сравниваются
   с независимым greedy decode; монотонный каркас проверяется последовательным
   matcher. Дополнительный текстовый контекст допустим только при слабом,
   но правдоподобном совпадении неоднозначного начала.
5. `LocalAcousticReads` хранит только реально прочитанные локальные окна.
   Запрос не длиннее 6 с; объединённое покрытие не выше 65% записи; суммарный
   вход модели не выше 200% длительности (учитываются повторные чтения).
   Это жёсткие пределы, не обходятся переменными окружения. Срез локального
   cache не считается новым inference. Запрос сверх лимита возвращает отсутствие
   доказательств. Cache всей суры, последовательное покрытие всего файла,
   FULL/tiled fallback в FAST отсутствуют.
   С 2026-10-14 бюджет списывается при начале вызова, включая ошибку/отмену:
   это консервативный учёт отправленного входа. В ledger шлюза каждый вызов
   имеет `outcome=completed/failed/cancelled`; frames учитывают только принятый
   успешный результат. Отмена проверяется до cache, перед и после inference
   в CTC и Whisper; отменённый/ошибочный ответ не кешируется. Отказ до вызова
   не расходует бюджет. Пределы 6 с / 65% / 200% не изменены.
6. Сохраняются проверки слабого начала первого аята, неполного CTC-пути,
   пересекающихся micro-пауз, порядка и спорных блоков. Только короткий блок
   может быть совместно выровнен внутри локального лимита. Длинный wasl-блок
   получает prior с confidence=0 для ревью. Глобальный drift/нарушенный порядок
   помечает результат для ревью, без автоматического полного чтения.
7. Опциональные аятные клипы той же записи проверяются локальной envelope-
   корреляцией; сеть не используется автоматически.
8. Уверенность и флаги → ревью. Ручные edited/verified сохраняются.

Trace: `model_reads`/`acoustic_reads` — реальные вызовы модели с абсолютными
интервалами и числом frames; `emission_passes` — число CTC-вызовов,
`model_passes` у Tarteel — число локальных ASR-вызовов, `audio_ms` —
суммарный вход с повторами, `covered_audio_ms`/`coverage` — объединённое
покрытие. `alignment_reads` — решения CTC на локальных frames, отдельно от
inference. `denied_acoustic_reads` объясняет отказ; `review_required_ayahs`
перечисляет неподтверждённые метки. FAST не гарантирует прежнюю точность режима,
который читал всю запись; измерения и ограничения приведены в
`docs/tasks/2026-10-13-fast-local-implementation/task.md`.

Tarteel Tiny/Base FAST сначала получает те же DSP/VAD-паузы. После каждой принятой
паузы независимо распознаётся 1.3 с речи с pre-roll до 200 мс; фраза сравнивается
с минимальным различающим началом известного аята (до 6 слов, с проверкой
повторов внутри суры). Только подтверждённый неполный/неоднозначный префикс
позволяет расширение до 2.5/4 с речи. Чтения проходят общий жёсткий бюджет,
дополнительно длина участка проверяется в RPC и worker. ASR не заменяет текст
Корана. Полное выравнивание, teacher-forcing и tiled fallback не вызываются.
Порядок подтверждённых пауз/аятов задаёт монотонный каркас; метка — центр
паузы. Неподтверждённое — структурный prior с confidence=0 и явным ревью.
FAST Tiny/Base не использует некалиброванные attention heads FULL.

На Шатри 78–114 Base: median 67.5, p95 1628.2, max 6062 мс; 64/564 ошибок
>500 мс и 153 метки ревью, 516.4 с без load/decode. Quran Phonetics на том же
наборе: 73.5/4465.85/26762 мс, 107 ошибок и 288 меток ревью, 136.3 с.
Base уменьшает общий хвост ошибок, но медленнее и оставляет 9 крупных ошибок
без флага ревью (Phonetics — 6); основная модель не меняется автоматически.
[Адаптер, реальные интервалы и сравнение](tasks/2026-10-13-tarteel-fast/task.md).

Tiny подключена к тому же локальному адаптеру без изменения thresholds.
Повторный прогон трёх моделей на идентичных паузах Шатри 78–114:
Tiny median 68, p95 1757.5, max 6062 мс; 72 ошибки >500 мс, 170 ревью,
8 ошибок без ревью из 394 подтверждённых. Время DSP+inference/matcher:
Tiny 243.8 с, Phonetics 133.3 с, Base 448.3 с, без load/decode.
Границы Phonetics/Base побайтово совпали с предыдущим прогоном; время зависит
от нагрузки. Tiny — промежуточный вариант по скорости и крупным ошибкам,
основная модель не меняется. [Замеры и проверки](tasks/2026-10-13-tarteel-tiny-fast/task.md).

ONNX-окна обрабатываются по одному: при dynamic INT8 совместная обработка
окна речи и заполненного нулями хвоста меняла границы. Это общее правило для
FULL, FAST, tiled и пословного режима.

FULL проверяет начало первого слова каждого аята отдельно; confidence
вычисляется по кадрам букв без blank, чтобы тишина не скрывала слабый первый
звук. Если слабый префикс пересекает единственную подтверждённую DSP-паузу,
а следующие звуки того же слова уверенно распознаны после неё, метка
перепроверяется по центру этой паузы. При недостатке доказательств метка
остаётся слабой для ревью. Неполный CTC-путь отклоняется без искусственных
меток; GUI сохраняет подробный FULL trace и confidence в `review_meta`.
При большом FULL-задании те же проверки выполняются в bounded tiles.

Штатный FULL ONNX Quran Phonetics с2026-10-14 использует `core/full_windows.py`:
акустические участки около20с,3 независимых ONNX-вызова одновременно,
в каждом batch=1. Сохраняются глобальная нормализация, сетка20мс и контекст2с;
центральные emissions соединяются перед прежним FULL/CTC. Внутренние cuts
только в строгих energy/contrast-паузах>=300мс, прошедших дополнительный DSP
gate против тональных хвостов.20с — ориентир; разрез по времени при отсутствии
паузы запрещён. Участок>60с вызывает явный отказ до inference, защищающий
память без скрытого разреза речи. Это подтверждение паузы по сигналу,
не доказательство границы аята.

Новая политика применяется и при переходе FULL к bounded CTC на длинных
сурах. Общее `_emissions`, явный tiled, FAST, пословный emitter и другие
модели/torch сохраняют собственные пути. FAST полный проход не вызывает.
Trace `full_windows` хранит реальные окна/metrics/решения по паузам и параметры;
source результата содержит window/workers/context/pause/review policy и предел.
Консервативное FULL-ревью дополнительно помечает неподтверждённый звук первого
слова (token confidence<.05) и позднее начало внутри длинной паузы
(>=700мс, позже центра на>200мс). Эти проверки не меняют время/confidence,
изолированы от FAST и восстанавливают предупреждения83:10/95:8 на проверенной
записи Шатри. Полной калибровки на114 сурах/других чтецах пока нет.

`tools/bench_full_windows.py` сохраняет отдельные cases fixed/pause/strong
и1–6 workers для read-only экспериментов; настройки/пользовательские БД он
не меняет. [Сводка всех замеров и решения](full-performance.md),
[включение и проверки](tasks/2026-10-14-full-default-20x3/task.md).

FAST применяет эту проверку к первому аяту. VAD может сузить энерго-паузу
после басмалы, но не расширить её назад в звучащее аудио. Добавляемые micro-паузы
не могут пересекать существующие паузы. Слабый wasl после похожих начал
с пропущенной trusted-паузой в коротком блоке без waqf проверяется совместно
между внешними опорами только в пределах локального бюджета; сомнительные владельцы
внутри блока не используются как его опоры.

Для воспроизводимого аудита `tools/bench_fast.py` принимает
`--ayah-audio-dir PATH`: он прогоняет тот же opt-in refine вместе с pause и
sequence контрактами.

## Модули

- `core/` — `decode`, `candidates`, `emissions`, `align`, `pipeline`.
- `data/` — `quran_text` (чтение `quran_mushaf.db`), `references` (эталоны/QUA),
  `project_db` (рабочая БД + merge), `export_db` (чистый экспорт).
- `gui/` — `app`, `dashboard_view`, `review_view`.
- `webgui/` — основной интерфейс: локальный FastAPI-сервер, webview, HTML/JS;
  `gui/` сохранён как прежний Qt-интерфейс.
- `cli.py` — батч.

## Данные

- `data/quran_mushaf.db` — таблица `words` (`qpc_hafs`): текст слов, карта
  слово→аят, число аятов на суру.
- `data/references/*.db` — ~45 размеченных чтецов (схема `timings`).
- `assets/fonts/qpc_hafs.ttf` — KFGQPC HAFS Uthmanic Script.

## Инварианты (не нарушать)

- Выход: схема `timings(sura, ayah, time)` (мс, старт аята) + `db_version`.
- Ровно 6236 аятов, 114 сур; `time` монотонно растёт внутри суры; число аятов
  на суру = из `quran_mushaf.db`.
- Соглашение про басмалу: для суры 1 аят 1 — басмала; для сур ≠1 вступительная
  басмала — интро, не приписывается аяту 1 (сверить с эталоном).
- Рабочая БД = валидная выходная БД + служебные таблицы (`review_meta`,
  `edit_history`); экспорт вырезает служебные таблицы.
- По умолчанию перегенерация не затирает `edited`/`verified`. Исключение —
  явный выбор «Перезаписать всё» в компактном окне возле Start (2026-10-14).
  API получает `overwrite_manual=true` только для этого запуска; новые
  результаты заменяют возвращённые моделью метки со статусом `auto`, а старое
  и новое время записываются в `edit_history`/`word_edit_history`. До успешного
  расчёта статусы не сбрасываются. Отмена/ошибка не удаляет старую разметку.
- Merge аятов/слов читает статусы и пишет данные в одной `BEGIN IMMEDIATE`
  транзакции. Проверяется итоговый порядок вместе с защищёнными метками;
  конфликт отклоняется целиком, включая confidence/history. Ручные записи
  проходят те же проверки. `force=True` не разрешает обход защиты.
- Strict-экспорт сверяет точный набор аятов с `quran_mushaf.db`, принимает
  только целочисленные неотрицательные старты со строгим порядком внутри суры.
  Экспорт поверх исходного проекта запрещён, включая ссылки на тот же файл;
  готовый экспорт заменяет назначение атомарно после успешной записи.
- Фоновая генерация использует снимок путей БД и аудио; её логи относятся
  к тому же проекту. Смена проекта во время фоновой генерации отклоняется.
- Возобновление пропускает только суры с полным каноническим набором аятов.
  Частичная ручная разметка сохраняется и не мешает досчитать остальные аяты.
  В Web GUI для явного режима также сверяется `requested_mode` auto-меток:
  другой, смешанный или неизвестный режим пересчитывается. Полностью защищённые
  суры пропускаются; words отдельно проверяет полноту слов и сохраняет границы аятов.

## Гарантии после ревью — 2026-10-13

- Транслитерация загружается из проверенного offline-cache: ровно 6236 аятов
  и 77432 непустых слов в каноническом порядке. `tools/build_transliteration.py`
  воспроизводимо согласует три известных случая объединённого `baʿdamā`;
  иные расхождения останавливают загрузку. Канонический текст не меняется.
- CLI/Web/Qt используют общие поиск аудио, определение полноты и writer.
  `review_meta.source` сохраняет модель, revision/хэш локального артефакта,
  backend, запрошенный/фактический режим и lag; confidence входит в транзакцию.
  Writer проверяет модельные границы до ручного overlay; непосредственно в
  транзакции перечитывает edited/verified и проверяет итоговый порядок/диапазон.
  Отмена до commit сохраняет прежнюю БД. После commit результат уже сохранён:
  ошибка подготовки/публикации JSON даёт `saved_with_diagnostics_error`, UI/CLI/Qt
  сообщают успех сохранения и предупреждение. SQLite и JSON не составляют одну
  транзакцию. Failed/cancelled inference получает отдельный best-effort sidecar
  с ledger, без записи таймингов. Native Qt проверен только сигнал-заглушками.
  Успешные явные FAST/FULL дополнительно сохраняют неизменяемые JSON-прогоны
  в `<project>.logs/runs`: отдельный UUID, время, источник модели/режим/lag,
  исходные модельные времена до ручного overlay и confidence. Формат history v2
  также хранит полный trace/run snapshot/evidence и реально сохранённые строки. История публикуется
  до замены latest-логов; ошибка merge не публикует новый прогон. При первой
  перезаписи старый JSON-лог этого режима переносится в историю. Снимки и логи
  лежат рядом с БД; при переносе проекта следует переносить и эту папку.
  Схема рабочей/экспортной SQLite не меняется.
- Генерация имеет `job_id`, bounded SSE-журнал на 512 событий, независимые
  курсоры, heartbeat и replay terminal. `/api/generate/status` сохраняет
  итог, прогресс и ошибки слов независимо от удаления старых событий.
  UI восстанавливает задание после reload/reconnect, отменяет только его ID
  и игнорирует запоздалые ответы другой суры/проекта или прежней разметки.
- Настройки сериализуют read/merge/replace одной блокировкой и используют
  уникальные временные файлы. Это защита писателей одного desktop-процесса.
- Recheck без содержательных акустических токенов или за пределами записи
  возвращает `insufficient_evidence`; такие аяты отдельно считаются непроверенными.
- Общие операции текста и строгая проверка CTC находятся вне FAST;
  его локальная фаза чтения выделена в `LocalAlignmentReads`, сохраняя бюджеты.
  CTC backtrace хранит uint8-переход, acoustic windows создаются на текущий batch,
  точная длительность кэшируется по stat-идентичности файла.
- Runtime RPC имеет deadline на запись и чтение (300 секунд startup/probe,
  1800 секунд inference), установка — 1800 секунд. Timeout завершает worker
  с ошибкой; другая модель не подставляется. Optional runtime устанавливается
  из включённых hash-locks со всеми транзитивными зависимостями.
- Wheel включает Quran DB, cache, model targets, эталоны, шрифт и static UI.
  Крупные веса остаются внешними; `SURAH_CUTTER_MODELS_DIR` задаёт их каталог.

## Пословное ревью

Общий селектор разметки содержит «Быстрый», «Полный» и «По словам»;
дополнительных пунктов auto/tiled в интерфейсе нет. Сохранённые значения
auto/tiled отображаются как «Полный» без перезаписи настроек при открытии.
Иконки трёх режимов: молния, аудиоволна и строки текста; выбранная
повторяется в шапке. «По словам» заменяет обычный список аятов пословным видом в той же области.
Каждый аят остаётся отдельной группой; его слова показаны горизонтальными
карточками в каноническом RTL-порядке. Под словом — редактируемое начало:
переключатель единиц выбирает секунды с тремя знаками или целые миллисекунды.
Голубые метки, управление плеером и прогресс относятся к словам. Выбор синхронизирован между главным экраном, ревью и настройками
и сохраняется при перезапуске.

Пословный режим рассчитывает все слова выбранной суры или всех доступных сур.
По умолчанию при полной аятной разметке существующие границы не пересчитываются;
недостающая разметка сначала строится FAST с обычной защитой ручных аятов.
При явном выборе «Перезаписать всё» повторно рассчитываются границы аятов
и слова; остальные запуски по-прежнему защищают ручные/проверенные метки.
Запись суры декодируется один раз для пословного прохода, каждый аят
выравнивается отдельно.
Ошибки отдельных аятов видны в логе и счётчике, остальные аяты продолжаются.
Продолжение пропускает только суры с полным актуальным набором слов. Кнопка
«Пересчитать слова выбранного аята» в инструментах запускает локальный расчёт
аята выбранного слова.

Для локального расчёта нужно проверить начало аята и начало следующего;
для последнего используется конец записи. ONNX/CTC сопоставляет только этот клип с каноническими словами
из `quran_mushaf.db`, выбирая транслитерацию по исходным индексам слов суры.
Дополнительная басмала в аятный клип не добавляется. Неполный CTC-путь или
неразличимые старты отклоняются без равномерной подстановки. Источник хранит
модель, режим ONNX/CTC и фактическую компенсацию задержки.

Голубые метки — начала слов; их можно перетаскивать или менять в редакторе.
Карточки компактны: номер открывает меню времени и цветных сегментов
«Не помечен» / «Нужно ревью» / «Всё хорошо» с подписями снизу.
Сброс статуса сохраняет время; смена статуса не обновляет устаревшие границы.
Без актуальной метки сегменты отключены; время можно обновить отдельно.
Escape/закрытие возвращает фокус на номер слова; меню остаётся открытым
после автосохранения, а ошибка показана внутри и сохраняет прежние данные.
Ввод сохраняется по Enter или уходу из поля; смена единиц не меняет тайм-код.
Клик по слову сразу запускает только его интервал. Общий Play и стрелки в
пословном режиме работают с выбранным словом; подсветка волны тоже относится
только к нему. Остановка планируется по длине интервала с учётом скорости;
последнее слово ограничено концом своего аята, включая паузу. Статусы слов `auto` / `edited` /
`verified` независимы от статусов аятов. Повторный расчёт сохраняет ручные и
проверенные слова и атомарно отклоняется при конфликте порядка.

Служебные `word_timings` и `word_edit_history` автоматически добавляются в
рабочий проект при открытии. Каждая метка хранит снимок границ аята: при их
изменении слово становится устаревшим, остаётся в проекте и требует обновления
перед проверкой/прослушиванием. Старые ручные данные не удаляются. Экспорт
по-прежнему содержит только `timings` + `db_version`, без пословных таблиц.

Сверка с эталонным чтецом: median абс. ошибки старта < ~150 мс, 95p < ~500 мс.

Whisper Tiny/Base. Короткие
описания в справке показывают замеры FULL на Шатри 112/114, macOS CPU: медианную ошибку
начала аята и время с загрузкой модели/словами первого аята. Это не сравнение
FAST и не оценка всего Корана. Остальные записи скрыты из каталога и выбора
через API; веса/технические specs сохранены для воспроизводимости. Прежний
скрытый выбор при запуске заменяется Quran Phonetics.
Tarteel загружаются только из локальных pinned `.bin` через `weights_only=True`;
связанный output embedding восстанавливается перед strict-загрузкой. Старые
процессоры сохраняют 50364 текстовых/служебных ID и 1501 неявный timestamp ID
до размера головы 51865. Цели используют вспомогательный Imlaey с огласовками.
У Tarteel отсутствует generation config: явно перенесены pinned метаданные
и heads исходных OpenAI Tiny/Base; heads не калиброваны для fine-tuning.
FULL уменьшает окно 30→20→10 с только при переполнении токенов, заново
ищет опоры и сохраняет отказ при недостаточных доказательствах. Tiny
отклонила Шатри 78; Base завершила с p95 1226 мс. Замеры Tarteel отдельно
считают decode/load/FULL/words и показаны в индивидуальной справке.
[Проверка и ограничения](tasks/2026-10-13-tarteel-models/task.md).

FAST доступен для Quran Phonetics и экспериментальных Tarteel Tiny/Base.
Выбор Tiny/Base сохраняет явно выбранный fast/full/words; unsupported auto/hybrid
не переходят в FULL внутри расчёта. Поле supports_fast публикуется в каталоге.
Отдельные замеры FAST показаны только в справке модели. Основная — Quran
Phonetics; ограничения — `docs/tasks/2026-10-13-tarteel-fast/task.md`.

Сохранённые runtime: MMS_FA и MMS Arabic используют собственные CTC-головы, Muaalem — ONNX phonemes
и SeamlessM4T-признаки, оба FastConformer — штатную CTC-голову NeMo с BPE.
В FULL все Whisper используют teacher forcing известного текста и attention-DTW; ASR
служит только для поиска текстового диапазона длинного окна, не заменяет Коран.
FULL ограничивает поиск ближайшим префиксом (до 180 канонических слов,
не более `max(12, 2 × число ASR-слов)`); несколько орфографических единиц
одного слова сохраняют один канонический индекс. Неподтверждённое ASR или
переполнение decoder budget повторяются на 20/10 с без пропуска текста;
после успешного продвижения окно возвращается к 30 с.
Если ASR завершился до конца речи, FULL перепроверяет участок до DSP-паузы
и начало после неё (до трёх пауз, без TEN/VAD). RMS-детектор расположен
в standalone worker: кадр 20 мс, сглаживание 5 кадров, минимальная пауза
300 мс, проверка контраста/глубокой длинной паузы. Ему не нужен импорт
пакета приложения в изолированном Python. Перейти через паузу можно
только при том же диапазоне слов до неё и подтверждённых первых словах
следующего диапазона. Времена берутся из повторного teacher forcing, а не
из центра паузы; непроверенный переход отклоняется. Изолированные начальные
буквы передаются как произнесённые названия букв с одним исходным word span.
Версия FULL-адаптера и параметры входят в source; FAST этот путь не вызывает.
Дополнительные модели поддерживают полный, точный и пословный режимы; FAST
с фонетическими эвристиками остаётся для Quran Phonetics; Tiny/Base имеют отдельный
локальный ASR/pause адаптер. Другие Whisper FAST не поддерживают.

Тяжёлые зависимости устанавливаются через uv в отдельные Python 3.11 окружения
`~/.surah-cutter/model-runtime` и `nemo-runtime` (раздельно из-за несовместимого NumPy).
Код приложения остаётся без импорта torch/NeMo; inference идёт в локальном
дочернем процессе. После выбора выполняется настоящий encoder/head probe.
Смена модели заблокирована на время расчёта. Неуспешная проверка сохраняет
прежний ID; его веса при необходимости загружаются заново.

`data/model_text_targets.json` содержит проверенные вспомогательные Uthmani/Imlaey
представления 77 432 слов из quran-transcript 0.6.4. Канонический текст/индексы
не меняются; runtime проверяет SHA исходной Quran DB и каждую выбранную запись.
Генератор — `tools/build_model_text.py`. Muaalem фиксирует Hafs, madd=4, waqf
по аятам; неизвестные фонемы и несовпадения слов отклоняются. Источник метки
содержит ID/revision, алгоритм, параметры, SHA этого словаря и версии runtime.
MMS_FA использует uroman и штатный MMS_FA classifier order без star/разделителя.

Скачивание больших файлов использует проверяемые HTTP byte ranges; перед
атомарной публикацией проверяются полный размер и SHA. Проверенные веса
сохраняются даже при ошибке подготовки окружения. При сетевом сбое частичная
загрузка остаётся для повторной попытки; отмена очищает её. Закрытые модели не включены.
Проверки точности и ограничения отдельных моделей — в задаче
`docs/tasks/2026-10-13-model-runtimes/task.md`; benchmark `tools/bench_models.py`
читает аудио и эталоны без записи в пользовательские проекты.

Действия каталога показаны иконками с подсказками и доступными названиями.
Удаление скачанной неактивной модели перемещает её каталог версии в
~/.surah-cutter/models/.trash. Локальные встроенные веса не удаляются;
во время расчёта удаление недоступно.

Технический реестр также содержит обычные OpenAI Whisper Small/Medium/Large-v3/
Large-v3-Turbo, NVIDIA FastConformer Arabic и Meta MMS-1b-all с ara-адаптером.
Для этих записей фиксируются runtime_family и language=ar; используются
только multilingual checkpoints. Файлы processor/tokenizer включены в
проверяемую загрузку, альтернативные .bin и остальные MMS-адаптеры исключены.
Общий runtime и его фактические проверки описаны в задаче model-runtimes.
