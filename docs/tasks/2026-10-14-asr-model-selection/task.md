# Выбор модели независимого распознавания Корана

Дата: 2026-10-14.

Цель: найти обоснованный вариант audio → text для FAST, FULL и слов, без
принудительной подстановки канонических букв при распознавании.

Скоуп: исследование первичных источников, проверка текущих адаптеров и доступных
локальных моделей; отдельные воспроизводимые probes. Настройки приложения,
production-код, пользовательские БД и канонический текст не менять.

Прочитано: `docs/project.md` (контракты режимов и runtime), релевантные записи
`docs/STATUS.md` и `full-accuracy/fatiha-model-comparison.json` (существующие
измерения и ограничения). Код `model_worker`, `model_runtime` и каталог моделей
проверяются для различения ASR и known-text alignment.

Решения:
- Не считать WER доказательством точности границ.
- FAST проверять только на отдельных локальных crop до 6 с; полное
  распознавание допустимо лишь в отдельном FULL-исследовании.
- ASR-гипотезы сравнивать с каноническими словами после распознавания;
  исходный Коран не подменять гипотезой модели.
- Результаты авторов и существующие измерения отделять от новых проверок.

Чек-лист:
- [x] Первичные источники и shortlist.
- [x] Проверка доступного независимого ASR / отказов runtime.
- [x] Вывод отдельно по тексту, FAST, FULL и тайм-кодам слов.
- [x] Отчёт, ограничения и STATUS.

Проверка: 42 финальных независимых ASR cases, 6 FULL-записей пяти чтецов,
local/shift/silence отдельно; post-decode оценка; Ruff. Отчёт: `report.md`.
Блокеры: широкая проверка всех режимов и word GT отсутствуют; native timing
не прошёл калибровку; Muno gated; штатный NeMo имеет dependency failure.
Гарантия стабильности на всех чтецах не подтверждена. Default не менялся.

Docs updated: task/report, `docs/STATUS.md`.
