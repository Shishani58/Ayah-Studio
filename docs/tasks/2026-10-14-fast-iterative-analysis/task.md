# Итерационный анализ FAST

Цель: диагностические прогоны согласованных 10 сур, причинный анализ ошибок
модели/алгоритма, узкие улучшения точности и скорости с парным сравнением.
Пользователь разрешил самостоятельные решения и запретил тесты до финала.
Прогоны benchmark являются требуемыми диагностическими экспериментами.

Прочитано: RTK, AGENTS/CLAUDE (идентичны), Serena manual, project.md
(контракт, набор), релевантный STATUS, cause-review/report и gap-fixes/task.
Исходное дерево грязное: существующие изменения сохранены initial-worktree.diff,
FAST baseline сохранён отдельно. Чужие FULL изменения не трогаются.

Решения: никакого FULL/покрытия всей суры, бюджеты 6s/65%/200%, только
независимые акустические доказательства. Reference применяется после inference.
Прежде правок приложения — измерения и причины. Исторические данные не заменяют
свежий baseline. Изменение модели/default не входит в задачу.

- [x] Свежий baseline 10 сур CTC/Tiny/Base и подробные логи.
- [x] Причинный разбор и эксперименты с более короткими/длинными окнами.
- [x] Узкие оптимизации после анализа и точное парное сравнение.
- [x] Один финальный запуск тестов, отчёт, STATUS.

парные выводы. Полная сура2 проверена, отдельные снимки/source hashes сохранены.
Наша правка — только optimization.diff; другие FAST/FULL изменения сохранены.
