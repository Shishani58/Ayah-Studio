# Возврат скорости FULL второй суры

Цель: установить причину 48-минутного GUI FULL и вернуть 4–5 минут без
изменения точности, эталонных подсказок или пользовательских БД.

Прочитано: AGENTS/CLAUDE, RTK; docs/project.md (инварианты FULL/FAST),
docs/STATUS.md (предыдущие проверки); full-pause-windows/task.md (исторические
замеры), core/full_windows.py, emissions.py, cancellation.py и GUI generation job.
Применён skill complexity-optimization: узкая оптимизация уже измеренного CTC,
без изменения цели выравнивания и точности float64.

Исходные факты: последний snapshot f3d858 — inference 2803.439s, DSP32.474s;
346 окон побайтово совпадают с c942087 (inference350.539s). Модель/audio SHA
и workers3 прежние. Короткая проверка в CLI: 6окон11.165s (default pool),
11.387s (threads4); это не воспроизводит 48мин и не обосновывает смену threads.

Решения: сравнить GUI cancellation/RunOptions, scheduling и штатный CLI;
замерять CPU/wall, затем полный штатный pipeline без записи в пользовательскую БД.
Сравнение точности — с сохранённым независимым text-only FULL результатом,
никогда не подавать старые времена в расчёт.

Решено: GUI activity с защитой от QoS clamp, сбор независимых FULL окон по
готовности с восстановлением исходного порядка; повторное использование
CTC scratch вместо матрицы кандидатов/argmax на каждом кадре. Float64,
tie order, ветка non-finite, backpointer uint8 и отмена сохранены.
Число workers3, ONNX options, веса, текст, DSP-окна и prior прежние.
Изменение intra-op, ручного QoS, workers4, memory arena и dynamic blocks
не включено: преимущества не подтверждены либо менялись logits.

## Дополнительное повторное сканирование FULL DSP

При проверке исправления weak-onset-silence обнаружено повторное вычисление
глобального RMS в detect_strong_pauses: _dsp_pause_metrics уже принимает
audio_rms, но caller не передаёт его, и вся запись умножается/усредняется
для каждой паузы. Это O(samples * pauses) вместо одного O(samples).
План: вычислить ровно прежний float32 RMS один раз, передать существующим
параметром; сравнить все метрики/окна побитово и полный native FULL.
Сначала завершить текущий native baseline, не менять исходники во время него.
Эта оптимизация не меняет критерии DSP, модельные чтения или FAST.

Выполнено: float32 RMS один раз,774 decisions/346 окон точно прежние,
DSP25.852→0.333s в полном native. Native v10 до/после:323.583→323.230s;
inference261.710→287.772s на загруженном хосте (0–0.7% CPU idle,
6.4–6.9GB compressor). Все286 rows/checks v10 и confidence прежние;
последовательность меток изменена отдельно по задаче weak-onset-silence.
1009pytest/10skip и5 настоящих FULL прошли. Стабильная цель4–5мин всё ещё
не подтверждена; отчёт о4:42 выше — один исторический контроль.
Полные артефакты новой проверки: ../2026-10-16-weak-onset-silence/.
Результаты и команды воспроизведения — в report.md и validation.json.
