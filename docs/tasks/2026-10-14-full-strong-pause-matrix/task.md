# FULL: сильные паузы, длительность и параллельность

## Цель и скоуп

До добавления настройки сравнить 25/30 секунд и 2–6 одновременных вызовов
на прежней длинной суре 42 Шатри (16:32 / 53 аята). Контроль — 20 секунд ×3
с той же новой политикой пауз. По три независимых процесса на комбинацию,
порядок блоков меняется. Настройку/GUI/штатный FULL/FAST не менять.

## Прочитано

- `AGENTS.md`, `RTK.md`: инварианты, task/doc workflow, запуск команд.
- `docs/project.md`: отдельный эксперимент, batch1, контекст2, FULL/FAST.
- `core/full_windows.py`, `tools/bench_full_windows.py`, tests: прежние окна
  допускали fixed fallback; новая политика должна быть отдельной.
- `candidates.detect_energy_pauses`, `_filter_contrasted_pauses`,
  `_dsp_accepts_pause`: уже имеющиеся проверки сигнала без новой зависимости.

## Решения

- Новый case kind `strong`, сохраняющий прежние `fixed`/`pause` для сравнения.
- Сильная пауза: refined low-energy shelf >=300 мс, прошедшая обычный строгий
  energy/contrast detector и дополнительный DSP gate, отвергающий тональные
  хвосты. Слабый второй проход и TEN rescue не используются. Это подтверждение
  тишины по сигналу, не доказательство границы аята и не ручная разметка.
- Внутренние cuts только в середине принятых пауз, на 20-мс сетке внутри
  паузы. Целевая длина приблизительная: нет fixed fallback и верхнего cap,
  который мог бы разрезать речь. Хвост до конца файла может объединяться.
- Контекст 2 с сохраняется, значит входы модели перекрываются; выходные
  центральные участки стыкуются без дублирования. Batch1, глобальная
  нормализация, канонические targets/CTC не меняются.
- Workers расширяются до6 только в отдельном эксперименте. Записывать
  принятые/отклонённые паузы, metrics, фактические окна и все ошибки к эталону.
