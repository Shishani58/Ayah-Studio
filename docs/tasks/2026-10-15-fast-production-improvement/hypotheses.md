# Проверяемые следующие причины

H9 — executor не использует целую независимо распознанную короткую ASR-единицу
внутри canonical word, чьё модельное представление содержит несколько слов.
Конкретный случай: canonical يَٰٓأَيُّهَا → actual Tarteel representation
('يا','ايها'). На65/73 Base слышит первое 'يا' с качеством .9376/.9988,
но expansion gate требует3буквы; twoletter unit не разрешает дочитать слово.

Изменяем только cue условие: matched1, первая единица ровно2буквы и первая
canonical word заканчивается после неё. Все существующие глобальные rival,
качество .6 и full canonical-word proof остаются. CTC состоит из односимвольных
единиц и эту ветку получить не может. Слабый/неуникальный fragment не разрешает
расширение. Никаких изменений ASR текста, canonical, defaults или времени.

Различающее наблюдение: на том же выбранном DSP candidate получится второй
локальный crop, который независимо вернёт обе части слова с полным качеством.
Проверка: fresh paired65/73 Tiny/Base, затем заранее выбранные Гамиди/Хусари65/73
из согласованного каталога. Эти короткие записи допускают небольшой download,
существующие audio80/98/112 не проверяют данный vocative failure. Reference
не открывается до predictions; не используется для окна, owner или порога.

Дополнительно: prior body-cue discovery с arabic_units(raw canonical) не равен
реальному Tarteel target. Реальный target берётся через adapter.represent и
inference_words. Ошибочную гипотезу о missing alif в canonical normalization
не реализуем: actual target table уже корректно даёт 'يا أيها'/'فأراه'.

H9a завершён: Base73 19→20 (+1прямое подтверждение,35callsвместо34);
Tiny неизменна. На65первое 'يا' имеет canonical rival 'يا اولي' внутри65:10,
поэтому условие уникальности не разрешило дочитать. Это объяснённое наблюдение,
а не отсутствие правильного opening в аудио.

H9b: так же как уже разрешённое полное короткое canonical слово, полная
независимая ASR-единица внутри multi-unit canonical word может объяснять
конечное разрешение неоднозначности. Уникальность требуется итоговому proof,
а не cue. Поэтому разрешается только обычное конечное расширение при
совпавшей целой двухбуквенной первой ASR-единице с качеством>=.6,
не truncated и без сильного противоречащего продолжения. Полная canonical
фраза и её rivals проверяются существующим путём; подтверждать одним 'يا'
по-прежнему нельзя. Предсказание до запуска: на65Base появится2.5sчтение,
которое либо докажет 'يا ايها', либо сохранит отказ; wrong 'يا اولي' не
должно дать подтверждение текущему ayah1. Проверить также last/no-future,
weak/partial/alias/forgedproof на финальном этапе. Sources раздельны,
H9a не переписан. Для подтверждения закреплены Гамиди/Хусари65/73 до их results.

H9b дал7новых Base proofs:2Шатри,3Гамиди,2Хусари; потерь нет. Новый
Hussary73:1 имеет reference disagreement679ms и DSP interval6180–9380ms
(радиус1600ms). Текстовый proof не ограничивает положение начала внутри
этой большой паузы. Без human labels это не закрытое время; H9b не переносится.

H9c сохраняет чтение/identity, но не публикует новое подтверждение времени,
полученное благодаря short-word cue, если радиус DSP интервала больше500ms.
500 — заданная продуктовая граница временного контроля, интервал2×500
выводится из геометрии, не оптимизируется по величине679ms. Reference не
передвигает метку и не выбирает окно/owner/score. Это консервативный отказ
при большой неопределённости, а не калиброванная оценка ошибки. Старые proofs
не меняются; identity сохраняется событием IDENTITY_ONLY, итог остаётсяreview.
Новые positive proofs несут cue_read_id; validator независимо повторяет cue,
проверяет конечное расширение того же окна и радиус. Временная ветка не получает
искусственной высокой уверенности от полного текста.

Хусари после обнаружения679ms — temporal development/regression, больше не
слепое подтверждение. До H9c результатов закреплён новый Minshawi65/73 для
подтверждения после freeze. Проверка Гамиди сохраняет ранее найденный эффект.
Неудачная первая сборка H9c завершилась assertion до модели; rootprototype-c
сохранён нетронутым. Рабочий H9c — отдельный prototype-c2. Missing Observation
import исправлен статически до первого acoustic run; SHA обновлён.

Preflight H9c пересмотрен до модели: отказ после дополнительного чтения мог
изменить бюджет и заблокировать прежний future route. Поэтому измеряемый H9c
root=prototype-c3: разрешение short-word expansion отклоняется ДО нового
model call для широкого интервала. Это возвращает исходное поведение кандидата,
не помечает целый аят identity по одному 'يا', сохраняет только SEARCH_CUE_ONLY.
Тот же guard применяется к future-prefix expansion. Proof/validator вообще не
расширяются: остаются полные прежние фразы, attribution и геометрия. Никаких
новых исключений validator, temporal scores или JSON схемы нет. Неизмеренные
prototype-c/c2 не переносятся. Canonical/auxiliary representations неизменны.

H9d до F after: новая неоднозначная short-word cue не должна становиться
stickyblock при неудаче дочитывания. Иначе ранее доступный следующий sparse
anchor скрывается. Новый путь сохраняет первоначальные plan/phrase и при
отсутствии полного proof возвращается к прежним кандидатам; все extra calls
остаются в ledger. Подготовлен behavioral regression с потерянной первой
границей и независимо прочитанной второй. Это защита existing recovery,
а не разрешение scan или подтверждения неполной фразы.

Первая D replay попытка:47совпадений, затем неизвестное окно Minshawi65Base.
Это именно открывшийся прежний candidate route после failed shortcue,
а не ошибка/новый вызов модели. Oldlog/partialJSON сохранены. Replayv2
использовал сохранённые actual before+after observations, сопоставленные
строго по PCM SHA:50/50rows те же,49/50windows те же. Minshawi65Base требует
дополнительных прежних baseline окон. Этот случай отдельно пройдёт fresh D.
Replay не выдаётся за новую акустику. F after и warm имеют historical filenames
*-prototype-c, но effective_variant=prototype-d и actualcwd/__file__/SHA явно
записаны; selected-wide-candidate.json закреплён ДО старта F after. Исторические
C roots/results не переименованы. После F/warm выполняется fresh D65/73 трёх
других чтецов; production перенос до этих проверок запрещён.

первой опоры до поздней паузы (самая ранняя CTC pause-read уже lam...).

услышанных CTC phones bis'mi; cue/forecast не являются временем границы.

Статическое ревью D: новая ветка не меняет подтверждение: целая canonical
фраза, глобальные rivals, essential minQ и исходный validator прежние.
Односимвольные CTC units не удовлетворяют `len(phrase[0]) == 2`; named-letter
proof boundaries также сохраняются. Неуспешные дополнительные чтения остаются
в общем бюджете, но не запирают последующие исходные кандидаты. Source patch
подготовлен в candidate.patch; текущий executor ещё имеет исходный SHA.

H9e из статического ревью: D мог удалить ранее установленный had_prefix block,
если новое short cue появлялось только на следующем дочитывании. Это шире
намерения: новый optional путь не должен отменять прежнее сильное свидетельство.

behavioral случай: первое чтение слышит полный последующий canonical word,
второе даёт только `يا`, третье не подтверждает; поздний повтор не принимается.

с равенством и rows, и windows, затем свежий E65/73 трёх других чтецов. Warm
выбирает E до своего старта; actual metadata это фиксирует. В случае хотя бы
одного отличия replay перенос запрещён до отдельного разбора. Replay не
выдаётся за свежий acoustic pass E114. Старые C3/D результаты сохраняются.
