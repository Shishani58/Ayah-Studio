# Уверенность и повторный запуск

Цель: показывать сохранённую уверенность машинной разметки и выполнять
выбранный режим при повторном запуске; edited/verified сохраняются.

Прочитаны: AGENTS.md/CLAUDE.md (инварианты), RTK.md (команды),
docs/project.md (merge, confidence, режимы), релевантные разделы STATUS.md.
UI: web-ui-ux и better-writing — существующий HTML/JS интерфейс.

Найдено: API отдаёт confidence, но UI его не использует. only_missing
пропускает полные суры независимо от режима. Known-reciter shortcut
обходит даже явно выбранные FAST/FULL/tiled.

Решения: отдельный цветной числовой показатель уверенности, без изменения
статуса ручной проверки; градации 0.33/0.66 как в Qt. Это оценка модели,
не процент фактической точности. Неизвестное/устаревшее не подменять нулём.
Возобновление явного режима учитывает requested_mode авто-меток;
явный режим не подменяется эталоном. Схема БД и контракт FAST не меняются.

Чек-лист:
- [x] UI: аяты/слова, ru/en, отсутствие/ноль/ручные/устаревшие метки.
- [x] Resume: другой режим, тот же режим, частичная и защищённая разметка.
- [x] Регрессии writer/API/pipeline, Ruff, JS, визуальная проверка.
- [x] Обновить релевантные docs и записать результаты/ограничения.

Блокеры: нет. В рабочем дереве много ранее внесённых изменений;
сохранять их, править только необходимые участки.

Изменены: `webgui/server.py`, `static/app.js`, `static/studio.css`,
`static/i18n.js`, `core/pipeline.py`; регрессии в `test_webgui_server.py`,
`test_pipeline.py`, `webgui_async.cjs`. Историческая confidence ручных меток
остаётся в БД, но API/UI не представляет её оценкой изменённого времени.

Проверка: вся suite — 541 passed, 7 opt-in skipped; Ruff всей базы,
JS syntax, diff-check. После финальной компоновки/точности отображения —
20 UI/localization тестов прошли. Регрессии подтверждают обновление авто-времён,
confidence и requested_mode при FAST→FULL, сохранность времени/метаданных
edited/verified, пропуск того же режима, mixed/legacy provenance,
полностью защищённые суры и отсутствие reference-подмены явного режима.

Реальное аудио: Шатри 114, Quran Phonetics INT8, macOS ARM64, default flags,
align lag 200 мс. FAST 1.77 с, FULL 3.67 с (включая decode, с общей загрузкой
модели в том же процессе): 6/6 меток обновлены, разница 20–90 мс.
Уверенность изменилась. [Результаты/модель/trace](audio-check.json).
Это проверка исполнения, не новое измерение абсолютной точности.

IAB 1280×720 и 390×844, светлая ru/тёмная en: все три цвета, score=0,
отсутствующая оценка, RTL, без горизонтального overflow и ошибок JS.
Через UI FULL-пересчёт 113 обновил времена и confidence; word-проход
разметил 23/23 слова с оценками. При смене пакетного FULL→FAST кнопка снова
доступна для двух полных сур. [Скриншот](confidence-ui.png).
Прогоны и настройки UI использовали временный проект; SHA256 пользовательской
БД и settings.json совпадает до/после. Работающее приложение и упаковка
не перезапускались; WKWebView/.app/Windows не проверены.
