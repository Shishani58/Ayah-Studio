# FAST: реализация пересмотренного результата и поиска

## Что сделано

Это не доказательство, что FAST достиг точности и скорости FULL. Удалена
первоначальная неверная постановка «обязательно вернуть число каждому аяту».
FAST возвращает только доказанные временные границы. В диагностике каждому
каноническому номеру соответствует доказанная граница или `unresolved` с
`start_ms=null`, нулевым confidence и причиной. Подстановка по длине текста
удалена, включая заполнение хвоста после отказа.

Идентификация и время разделены: уникально услышанный текст возле паузы может
быть поисковой опорой при непригодном DSP midpoint. Эта опора не превращается
в выдаваемый тайм-код. Безопасные временные границы и внутренние поисковые
опоры хранятся отдельно. То же относится к первому ASR onset без timestamps.

После локального отказа можно проверить следующий самостоятельный canonical
случай, учитывая пропущенный текст только при выборе кандидатов. После двух
таких неудач проверяется **одна** DSP-пауза другого unresolved участка.
Длительность и текст номинируют гипотезу; реальный owner определяется только
полной независимо услышанной различающей фразой. Время в gap не восстанавливается.
Это другой путь входа в запись, а не увеличение допустимого номера будущего
аята у старого кандидата. Он общий для CTC/ASR; автоматического полного прохода
или сканирования всех пауз нет. Лимиты 6 s / 65% / 200%, cache 32 MiB сохранены.

Значения `2` ближайших targets и `1` дальней паузы — конечные исследованные
ресурсные ограничения, **не установленный оптимум**. После их отказа остаётся
явный нерешённый хвост. Полнота FAST не заявляется.

## Сквозная семантика partial

- `result_contract=partial-v1`, `surah`, `ayah_count`, `result_complete`,
  `unresolved_ayahs`; `boundaries`/`ayahs` покрывают канонические номера, а
  `rows`/`generated_rows` включают только разрешённые времена.
- Даже пустой модельный результат сохраняет trace и историю. Штатный writer
  под транзакцией удаляет старые auto FAST предложения для отсутствующих новых
  ключей. Ручные статусы защищены; независимые auto FULL остаются со своим
  источником. Удаление и запись откатываются вместе при конфликте/отмене.
- Неявный FAST для режима слов имеет `actual_mode=fast`. Старые FAST estimates
  с confidence 0/None скрыты из effective review/words, не дают resume/complete,
  не экспортируются с потерей provenance. Пользовательская БД вне writer не меняется.
- Плеер использует только непосредственный следующий canonical аят как конец.
  При неизвестном конце single/repeat не запускается и не продолжает играть.
  Частичный итог и число unresolved доходят через SSE/reconnect/UI/Qt/CLI.

## Измерения: завершённые различающие данные

`baseline.jsonl`: свежий исходный runtime, 4 суры Шатри, обе семьи моделей.
Никакой reference не читается программой расчёта; внешний `evaluate.py` читает
только уже сохранённые предсказания. Ошибки ниже — к внешней БД, не к независимо
размеченному физическому onset.

| Base 80 | 33 / 42 | 69 | 411.7 |
| Base 112 | 4 / 4 | 6 | 70.6 |

Первая структурная абляция (`identity.jsonl`), без дальней landmark: Base 2
**2→27**, 169 calls / 850.9 s, 259 unresolved, новых >500 ms нет. На 78 эта
абляция остаётся 0: геометрия была не единственной причиной тупика.

Вторая структурная абляция (`reentry.jsonl`): Base 78 **0→11**, 37 calls /
162.6 s, но новый midpoint 78:36 расходится с reference на 654 ms. Этот результат
не принят как пригодный. В акустике owner установлен, DSP interval нестабилен;
само распознавание текста не подтверждает его середину. Для новой отдельной
поисковой цепи нестабильный, как и широкий, midpoint оставлен unknown. На тех же
сохранённых опорах temporal-only replay оставляет **5** времен; это не свежий
inference/latency benchmark. Число/положение времени не подгонялось к reference.
Окончательный hybrid дал 39 времён, но выявил ещё +850 ms на 2:58: нестабильный
узкий DSP interval после ближайшего re-entry. Поэтому один и тот же консервативный
принцип применяется ко **всем новым независимым цепям**, ближним и дальним.
Root context и logical cache queries сохранены в downstream proof; финальный
validator повторно проверяет его и временной gate после JSON serialization.
Ни одно время не сдвигается к reference. Финальный точный replay 231 уже
полученного PCM наблюдения — **29 времён / 286**, 257 unresolved, без новых >500 ms,
без потери/сдвига исходных двух. Свежих модельных вызовов в финальном replay 0;
85.2 s replay не являются модельным wall-time benchmark. Для получения новых
наблюдений hybrid потребовал 62 настоящих дополнительных вызова относительно
169 в первой абляции.

Сравнение wall time не причинное: host нагружен, измерительные процессы
пересекались. Более короткий PCM у текущего Whisper всё равно дополняется
нулями до 30 s encoder input; расширение повторяет дорогой encoder. Скорость
пропорционально input-ms не предполагается, превосходство над FULL не заявлено.

## Другая постановка применения QPC

`ctc_graph_probe.py`: exact CTC substring graph с KMP state и unrestricted
complement probability. В отличие от prefix proof он допускает неизвестную речь
перед известной фразой. CTC повторы/blank проверены исчерпывающим перебором
малого графа. Проведены локальные реальные чтения тех же PCM, включая более
длинные 4.2 s crops правильных openings, и нулевые контроли; posterior npz/SHA
сохранены. `graph-results-v2.json`: ни одного разрешённого identity candidate.
Например, правильный 2:3 имеет prefix≈4.07e-8 и substring≈4.09e-8: перестановка
начала графа не исправляет несовпадающую фонетическую последовательность.

Это отличный от прежних beam/prefix posterior опыт, **отрицательный результат**.
Порог не ослаблялся; graph не перенесён в runtime. Даже положительное событие
«фраза встретилась внутри crop» потребовало бы проверки начала слова, rivals
внутри слова/через seam и отдельного timing. Этот exact-prefix/subsequence reader остаётся слабым в данных условиях.
Это вывод о конкретном способе применения, не о бесполезности весов.

Дополнительный `ctc_rank_probe.py` на **тех же сохранённых posterior**, без новых
model calls, сравнил full-window CTC likelihood правильного текста, всех
канонических word-start rivals близкой длины, одинаковой длины случайных строк,
blank и unrestricted best path. Выведены raw/per-token/per-frame scores; прямой
rank сравнивает только одинаковые token counts. На более длинных корректных
2:2/2:3 target имеет rank **1 из 944 / 1 из 937**, с log-likelihood выигрышем над
blank +116/+110, хотя exact prefix probability крошечна. Значит, отсутствие
свободного exact decode **не означает**, что веса не различают известный текст.
Но 80:1 остаётся rank6/27; на неверном коротком 80:2 ожидаемый target бывает rank1,
при этом проигрывает blank. Нули и чужая речь требуют отдельного отказа.
Чистый rank не является evidence и не перенесён в runtime; unknown/garbage gate,
варианты фонетической цели и seams остаются предметом следующего исследования.
`rank-results.json` содержит все 14 наблюдений, включая два нулевых контроля.

## Проверка и воспроизводимость

Точный свой diff против полученной грязной копии: `implementation.diff`;
свои пути: `implementation-files.json`; source/SHA: `implementation-review-*`.
Чужие изменения, в том числе удаление reference из runtime, туда не включаются.
Исходный предоставленный snapshot: `lead-baseline-source.zip`.

Промежуточные тестовые логи сохранены; финальные результаты перечислены ниже.

Два избыточных измерительных процесса `identity`/`reentry` остановлены SIGINT
после сохранения нужных завершённых случаев, чтобы освободить CPU финальным
межчтецовым проверкам. Завершённые JSONL содержат точный ledger. У measurement
скрипта не было checkpoint каждого dispatch: незавершённый случай не сохранён,
число его вызовов неизвестно; он исключён из любых totals и оценки качества.
Это ограничение исследовательского runner, не объявление нулевой стоимости.

## Остаточные риски

FAST всё ещё может выдавать мало времён; manual workload не измерен. Число
unresolved не скрывается. Модельная уверенность не калибрована как вероятность
точного разреза. Reference не является физической разметкой onset. Новая
проверка дальней паузы может не найти owner; один такой отказ не доказывает,
что в остальной записи нет доступных опор. Полный corpus/слуховая приёмка не
проведены; изменения не коммитились, пользовательские БД не записывались.

## Финальный source freeze и воспроизводимость

`final-frozen-replay2-source.zip` и одноимённый `-source-sha.json` сохранены
**до запуска**; включают текущий runtime, runner и проверку dispatch. Runner
не загружает модель, не читает reference, запрещает перезапись артефактов и
отказывает при отсутствии наблюдения для точного PCM SHA/числа samples.
Все 6 Base случаев завершены: Шатри 2/78/80/112 = **29/5/33/4**, Гамиди
80/112 = **10/1**; ledger запросов **231/37/69/6/49/3**, новых model calls **0**.
Исходные baseline keys/times сохранены, новых >500 ms нет. Все input identities,
partition и бюджеты проверены независимо ведущим агентом в
`lead-final-replay-verification.json`. Wall time этого replay не является
скоростью модели. Первый `final-frozen-replay` успел сохранить 4 случая и
остановился на неверном ключе чтеца; сохранён отдельно как незавершённый.

В старых `current-hybrid2.jsonl` и `final-replay2.jsonl` верхнее поле
`source_sha256` было ошибочно скопировано из baseline и не описывает
исполненный replay. Их rows/trace/run key не переписывались. Историческая
подпись loaded code находится в `trace.run_snapshot.implementation_sha256`;
для `final-replay2` и fresh80 это `58fd5af2…`. Точного архива исполнявшегося
executor `e61846…` нет; старый review archive содержит более ранний `e6c7a894…`.
Это ограничение воспроизводимости старых measurements, не задним числом
устранённый подписью current source факт. Полный drift и SHA файлов сохранены
в `measurement-provenance.json`. Между fresh80 и freeze изменились executor
(финальный validator gate), server и project_state; свежие measurements не
выдаются за проверки неизменного финального runtime.

Текущий source scheduler отдельно воспроизведён на 6 Base случаях выше.
`final-revalidation2.json` дополнительно проверяет текущим validator 12 уже
сохранённых ASR/CTC outputs: **12 passed**, без inference/reference. Это structural/acoustic проверки
доступных сохранённых полей. Старые proofs не всегда содержат новый
independent-target/root context: validator не восстанавливает его из ничего
и не подтверждает задним числом новый temporal gate для промежуточных 21
у Гамиди. Новый gate подтверждён именно current-source scheduler replay с 10.
Это также не проверка тождества CTC scheduler. QPC не получил
нового scheduler replay: полный posterior не сохранён в ledger. Это явное
ограничение; FAST QPC с высокой полнотой не решён.


Финальная узкая проверка контракта после freeze: **48 passed / 1.00 s**
(`final-contract-tests.log`); scoped Ruff runtime/tests/tools/scripts, JS syntax,
