# Перестройка FAST после независимого пересмотра

## Поручение

Пользователь требует подвергнуть сомнению все принятые решения, передать
реализацию субагенту и затем выполнить независимое ревью ведущим агентом.
Цель — точность и скорость полезного результата. Только очередного отчёта,
ослабления порога или sparse-N исключения недостаточно.

## Что пересматривается с нуля

| Прежнее решение | Основание сомневаться | Проверяемая альтернатива |
|---|---|---|
| На каждый аят обязательно вернуть число | Ненайденное время не является временем; export теряет confidence | Частичный результат с явными unresolved; без вымышленных времён в timings |
| Начинать продвижение только после подтверждения предыдущей границы | 2/286 Бахары; длинный хвост не исследуется | Планировать локальные наблюдения по независимым опорам, не распространять локальный отказ на всю суру |
| Одна цепочка: распознал opening → определил владельца → принял время | Сильная identity может существовать при ненадёжном midpoint | Разделить search/identity anchors и публикуемые timing boundaries |
| Свободное exact opening — основной способ применить известный текст | ASR может ошибиться буквой; фраза при этом различима по акустике | Локальное known-text/rival/unknown scoring на тех же PCM; без принудительного положительного ответа |
| Глобальная уникальность первого фрагмента обязательна для любого продвижения | Одна неоднозначность блокирует путь; соседний контекст уже содержит сведения | Несколько допустимых владельцев и контекст для выбора; порядок/темп не заменяют акустический proof |
| Фиксированный маленький crop всегда экономит время | Повторные decode и слабый контекст могут стоить дороже одного достаточного | Конечный выбор минимального достаточного контекста, измерять фактические encoder/decoder calls |
| Midpoint любой принятой паузы — правильный target | Physical onset и playback cut различаются; confidence не калиброван | Хранить основание времени отдельно, неизвестное оставлять unresolved; не подгонять к reference |
| FAST полезен, потому что читает мало аудио | Низкое покрытие делает wall time несопоставимым с FULL | Сравнивать скорость и ошибки при сопоставимой полезной работе, учитывать незавершённую разметку |
| Нужны новые веса/большой rewrite | Причиной может быть scheduler/decoding; часть вариантов уже испытана | Сначала причинная абляция на существующих наблюдениях и весах |

Паузы как единственная основа также не считаются научно доказанным оптимумом.
Однако локальный pause-first FAST — прямое обязательное условие пользователя
в AGENTS. В этой работе его нельзя молча заменить полным/скользящим проходом.
Ускорение FULL — реальный конкурирующий путь, но полный pass не называется FAST.
Обязательные canonical текст/число аятов, защита ручных данных, независимость от
reference и отсутствие скрытого полного чтения не являются отменяемыми
эвристиками. Произвольные бюджеты/пороги можно критиковать; повышать их ради
красивых цифр без причинного опыта не требуется и не разрешается этой задачей.

## Реализация: ожидаемый результат

1. Убрать автоматическое заполнение ненайденных времён из результата FAST;
   провести частичный результат через CLI/API/UI/writer/resume/export. Старые
   auto estimates не должны считаться новым доказанным результатом. Не чистить
   пользовательские БД в обход штатного writer, ручные метки неприкосновенны.
2. Изолированно проверить структурный способ продолжения поиска после локального
   отказа: раздельные identity/search anchors и timing boundaries, адресное
   переобнаружение независимых опор. Выбирать локальные паузы по конкретной
   неопределённости, не сканировать моделью всю запись по сетке или всем паузам.
3. Не считать косметическое увеличение +N основной целью. Как минимум сравнить
   current baseline и структурный прототип на одинаковом PCM/наблюдениях,
   затем выполнить свежие реальные прогоны и отрицательные контроли. Принять
   только вариант с воспроизводимым полезным эффектом без ложных времён/owners.
   Если первый вариант не сработал, диагностировать причину и проверить следующую
   существенно отличающуюся гипотезу; не завершать работу после первого отказа.
4. В production переносить проверенное; не маскировать неудачи ни пустым
   результатом, ни выдуманными оценками. Сохранить воспроизводимый итог,
   неизменённые FULL/канонические/ручные данные и точно описать ограничения.

## Проверка

- Реальные локальные PCM reads и trace/ledger, отсутствие whole-surah inference.
- Нерешённые границы не превращаются в времена; end-to-end partial result.
- Новые независимые опоры после реального unresolved-блока; контроль повторов,
  внутреннего waqf, тишины/чужой речи/обрезанного opening и first ayah.
- Сопоставимые before/after и несколько чтецов; frozen replay подписан отдельно.
- Скорость/RSS с учётом цены новой работы; успех по скорости не выдумывать.
- Целевые регрессии и полный итоговый pytest, scoped Ruff/JS, diff-check, sync.
- Независимое ревью ведущим агентом и исправление его существенных замечаний.
