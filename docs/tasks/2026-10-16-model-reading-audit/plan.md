# Конкретный план улучшения FAST после проверки чтения моделей

Дата:16октября2026. Основание: findings-deep.md и реальные local probes.
Это план реализации; изменения рабочего алгоритма в этой задаче не выполняются.

## Цель

Восстановить покрытие и точность FAST, сохранив безопасное отклонение неверных
меток. Главная метрика — качество всех итоговых времён и число требующих ручной
проверки участков; отдельно owner, cut error и количество acoustic proofs.
Число подтверждений само по себе не является целью.

Начать с одной установленной Tarteel Base. Новые веса/модели, массовое снижение
quality gates и обучение не нужны для первого проверяемого шага.

## 0. Зафиксировать актуальную точку отсчёта

Сначала принять завершённые изменения параллельной fast-production-improvement
в новый frozen snapshot: их65/73 fixes не выдавать за прирост этого плана.
Зафиксировать source/weights/config/runtime/policy, PCM и DSP pool SHA.
Исторические411→302/564 и130/607 не называть текущим benchmark.

Подготовить paired current-vs-candidate harness на одинаковых исходных audio/DSP,
с actual PCM dispatch spy, ledger, cold load/encoder/decoder/DSP/other/RSS.
Сравнивать доказанные/расчётные времена, owners, интервалы, причины отказов и
длину blocked blocks. Не подавать reference в поиск или выбор crop.

Артефакты: baseline.json, per-record-table.csv, causes.json, source-manifest.json.
Причины различать: missing pause; geometry rejects before reading; wrong window;
not enough context; decoder ambiguity; quality; repeated owner; unsupported timing;
budget; downstream blocked. Один блок не считать множеством model failures.

Проверка исходного регресса: воспроизвести37пар legacy/current с одной Base
и одинаковым pinned bundle в изолированных snapshots, без сброса грязного checkout.
Если часть legacy несовместима, сохранить точный отказ, не подменять baseline.

## 1. Первый прототип: адресно дочитывать ближайшую новую опору

Проблема:2:4 уже читает candidate у50120мс, но короткое أُولَى не разрешает
дочитать начало2:5. Свежий4с crop даёт أُولَئِكَ عَلَى هُدًى.
Текущие sparse anchors/expansion существуют; расширяется конкретное условие
дочитывания, новый parallel scanner или общий matcher не создаётся.

Что сделать:
1. Уже прочитанный сильный **неполный** head рассматривать как search cue для
   конечного перечитывания той же паузы. Cue не подтверждает аят/время.
2. Сопоставлять cue симметрично с ближайшими canonical starts и внутренними
   фрагментами. Первым вариантом проверить сужение на неполном слове по общим
   буквам и акустическому признаку продолжающейся речи у правого края.
   Если совпадающих owners много, cue разрешает только сбор дополнительного
   материала, но не выбирает ожидаемый owner по темпу.
3. Использовать существующие размеры1,3→2,5→4с; расширяться только при
   зафиксированной неоднозначности. Окончательное proof — полный различающий
   текст, essential quality≥0,6, отсутствие сильного противоречия, все rivals,
   geometry/time и прежний общий validator. Пороги proof не снижать.
4. Разрешить проверить текущий/непосредственный следующий opening из этого же
   чтения в существующем bounded recovery; физический lookahead максимум2аята.
5. При неудаче вернуть прежний поиск/решение, не терять уже доказанные опоры.

Файлы:fast_executor.py (_expansion_evidence, align_surah_sequential),
tests/test_fast_algorithm_gaps.py и целевой regression рядом с existing tests.
Runtime/модель на этом этапе прежние.

Обязательные случаи:2:5 у50120; внутреннее2:5 у56740 должно отклоняться как
opening;65:1,80:12,79:27 — адресное дочитывание; чужие фразы/нули/повторы/
обрезанный head/отмена/лимиты. До изменений повторить на latest baseline.

Критерий локального успеха: реальный end-to-end FAST на суре2 получает новую
валидную опору после проблемного2:4 и реально продолжает обработку. Сам2:4
может остаться review. Не обещать восстановления282меток из одного local probe.
Нужны новые подтверждения и у других чтецов; сохранившиеся conf0 не маскировать.

## 2. Отделить право прочитать речь от права поставить точную метку

Проблема:decaying_tail_midpoint_unproved сейчас запрещает прочитать opening
у правого края паузы. На2:4 этот opening акустически восстанавливается.

Сохранить исходный temporal verdict, но допустить один локальный identity-read
в уже выбранном DSP-кандидате. Для его интервала нужны измеренные speech edge,
правильная длина и бюджет; rejected midpoint сам не становится valid cut.
Полное opening доказательство сохранять отдельно как identity/cue, не как
Boundary с надёжным временем. Использовать его для адресной перепроверки или
поиска следующей опоры существующим recovery.

Файлы:fast_executor.py (pause_geometry call site и branches),
fast_reads.py только если нужен дополнительный scalar provenance;validator
должен явно отвергать повышение temporal confidence из identity-only evidence.
Канонический текст и формат SQLite не меняются.

Контроли:2:4 положительный identity;1:4 rejected pause читает следующий аят
и не подтверждает مالك. Нули, чужой owner, длинный decaying tail, внутренний
разрыв, совпадение одной общей фразы, невалидный order, отмена и ошибка inference.

Причинный2×2 на одном frozen corpus:
- A:baseline;
- B:только новые условия адресного дочитывания/recovery шага1;
- C:только identity-read при rejected temporal midpoint;
- D:B+C.

Выбрать минимальный вариант с подтверждённым вкладом; не переносить оба,
если второй только добавляет вызовы. Сомнительную точку не двигать автоматически.

## 3. Ограниченное восстановление после локального отказа

Проверить, что выбранный прототип не остаётся полезным только для2:4/2:5.
В пределах уже разрешённого локального lookahead собрать несколько hypotheses
для текущего блока, включая unknown. Только полностью доказанная будущая опора
разрешает продолжение. Пропуск не делает предыдущий аят verified/confident;
интерполяция остаётся явно estimate. Существующий sparse-anchor механизм
расширять, а не дублировать новой глобальной системой.

Отдельно измерять:сколько root failures устранено, сколько блоков укоротилось,
сколько downstream аятов получили **свои** proofs, максимальную/медианную длину
blocked block и качество итоговых времён. Показать числа по каждой записи,
чтобы сура2 не скрыла ухудшение остальных.

Не превращать recovery в обход всех пауз или чтение всей записи окнами.
Если положительного восстановления нет без такого обхода, оставить review и
зафиксировать предел метода. Полный проход остаётся отдельным FULL.

## 4. Только после этого — условный ASR n-best

Основание:на6исходных проблемных crop beam5 не дал ни одного нового прохода
необходимых opening-условий. На расширенном98:8 и Гамиди80 есть кандидаты,
но также ошибочные ветви. Всеобщее включение beam5 пока не обосновано.

Первый эксперимент — n-best как **cue для проверки**, а не выбор удобной
канонической ветви с отменой сильного greedy contradiction. Сохранять каждый
selected BPE/token score/owner, EOS/truncation, decoder rank и rival branches.
Нельзя переносить quality greedy на другую ветвь или суммировать коррелированные
ветви как независимые доказательства. Старый _beam_view предназначен для CTC
с positions/null; подавать туда ASR hypotheses без отдельного контракта нельзя.

Файлы:model_worker.py (whisper_local/private decoding method),model_runtime.py,
fast_adapters.py (Observation/TarteelAdapter),fast_executor.py (explicit ASR branch),
tests/test_model_runtimes.py,test_tarteel_fast.py,test_fast_reads.py.
Учесть различие Whisper.generate(num_return_sequences) и истинного n-best,
compute_transition_scores с beam_indices, EOS/padding и язык/task/prefix.
Проверить совпадение greedy с текущим runtime до сравнения улучшений.

Первый изолированный A/B может повторно считать encoder с полным учётом вызова.
После доказанного выигрыша исследовать encoder reuse **только локального crop**.
Не вводить долгоживущий cache скрытых состояний всей записи. Cache/run key
обязан учитывать decoding policy; live buffers и cached observations вместе
должны укладываться в установленный бюджет памяти.

Критерий переноса:новые прошедшие весь validator proofs на отдельном corpus,
ноль новых wrong-owner/negative accepts, отсутствие потерь прежних proofs и
приемлемая измеренная стоимость. Если полезен только cue, перенести только cue.
Если прирост отсутствует — production greedy остаётся, работа не маскируется
пересчётом confidence.

## 5. Точность времени — отдельная ветка с явной целью

Identity proof определяет текст, DSP определяет кандидата; ни один автоматически
не доказывает physical speech onset. Сначала отдельно зафиксировать цель:
начало звука и допустимый playback cut interval. При паузе возможен безопасный
интервал разреза; при wasl такой интервал не предполагается.

Подготовить60transition clips пяти чтецов с разными паузами/wasl/decaying tail,
без показа предсказаний/reference. Отметить конец предыдущей речи, начало
следующей, owner и допустимый cut interval.20неоднозначных примеров проверить
вторым разметчиком; разногласия хранить, не превращать в единственную точную метку.
Числа60/20 — предлагаемый объём будущей приёмки, не уже собранный эталон.

Только после этого сравнивать estimator cut/onset. До разметки доступны
benchmark-error и риск-регрессии, но не утверждение о физической точности.
Прежние неудачные attention-DTW/midpoint способы не включать повторно без нового
основания. Покрытие шага1–4 можно исследовать до ручной разметки.

## 6. Общие ворота и перенос

Данные для разработки:диагностические случаи этого отчёта, зафиксированный
Base12 и выбранные записи других чтецов; они уже не holdout. До подбора rules
назначить отдельные **целые** записи/суры на контроль, зафиксировать manifest;
не смешивать соседние окна одной записи между development/control.

Предлагаемые критерии перед началом будущих опытов:
- Положительный полный validator результат на≥3чтецах, с полными пофайловыми
  before/after, не только совпадением unaffected rows. Затем114сур Шатри и
  доступные записи остальных чтецов. Отдельно повторить legacy37 сравнение.
- Ноль изменений edited/verified; прежние доказанные времена/owners не терять
  на identity/recovery этапах. Любое расхождение разбирать построчно.
- Ни одной новой подтверждённой ошибки>500мс к packaged benchmark на контрольном
  наборе; ошибки estimates считать отдельно и также показывать. Это regression
  gate, не подмена human onset/cut accuracy.
- Все negative/повторы/внутренние starts остаются отвергнутыми. Failed/cancelled
  inference учитываются, RPC/worker отменяются, stale resume не используется.
- Каждый model read≤6с, union≤65%, суммарный recording input≤200%, cache≤32MiB;
  не повышать лимиты ради прохождения. Нет whole-emissions/tiled/FULL fallback.
- Предлагаемый предел стоимости:median общего тёплого FAST не хуже baseline
  более чем на25%, p95 не более2×, peakRSS без необъяснённого роста. Это
  проектные критерии, не измеренные свойства. Если beam не укладывается, делать
  его адресным либо не переносить, а не скрывать decoder cost.
- Цель по полезности:сначала устранить воспроизводимый cascade и получить
  независимые gains; затем двигаться к legacy coverage **при сохранении новых
  проверок точности**. Нельзя приравнять старые эвристические подтверждения
  новым proofs или закрыть задачу только меньшим числом confident errors.

Переносить по одному прошедшему этапу. Обновить VERSION/algorithm fingerprint,
run_snapshot/diagnostics и resume, docs/project.md, STATUS и task.
Запустить целевые FAST/runtime/accounting/persistence tests, затем один общий
pytest/Ruff/JS regression при изменении runtime/schema в traces; GUI smoke
выбранной Base на настоящем audio. Независимо проверить отсутствие записи
в protected данные и идентичность AGENTS/CLAUDE. Без коммита/пуша.

## Что сейчас не является первым шагом

Смена модели, переобучение QPC, общий CTC segmentation, переключение RNNT,
глобальный graph decoder и новое confidence scoring. Они остаются возможными
ветками, если адресные исправления не проходят gates. Сейчас есть измеренные
локальные пути с установленной Base; начинать с более широкой перестройки
не требуется.

Исследование завершено; реализация и end-to-end gates впереди. Главный открытый
внешний блокер physical timing acceptance — независимая слуховая разметка.
