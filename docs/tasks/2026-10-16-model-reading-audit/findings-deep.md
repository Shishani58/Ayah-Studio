## 2. Ранее приведённый пример80 не был приростом FAST

Текущий plan_phrase для80:1 требует только ('عبس',), а для98:2 — ('رسول',).
Оба слова уже правильно распознаны коротким greedy. Все4начальных примера

greedy. Исправление второго слова во втором beam — реальное улучшение текста,
но не доказательство новой подтверждённой границы FAST.

## 3. Проверены token-quality и реальные отказы

Новые27encoder evaluations:4предыдущих примера;6выбранных заблокированных
участков×исходный/4с контекст;8фрагментов3других чтецов;3negative controls.
На каждом encoder output выполнены greedy и настоящий beam5, сохраняются

Проверены lexical opening, min essential quality≥0,6, EOS и strong continuation.

Дочитывание даёт сильные openings на65:1,80:12,79:27. На98:8 короткий

с ошибочным جنة вместо جنات. У Гамиди80 похожий strong continuation conflict.
В обоих случаях есть более подходящие beam-ветви, но там же есть неверные ветви,
проходящие необходимые opening-условия. Выбор удобной нижней ветви не разрешён
как готовое подтверждение; нужна дополнительная проверка, а не снижение порогов.

На32:1 и2:4 выбранное дочитывание не помогло: слышится другая фраза. Это
показывает предел улучшения decoder на неподходящем фрагменте.

Transfer-case выбор biased: существующие target-pause reads выбирались по
историческому сходству текста. Это проверка механизмов, не representative accuracy.
Для Миншауи98:2 исторического target-pause чтения не было; случай записан как
skipped, новый crop по reference не подставлялся. Правильность владельцев
плохих crop отдельно слухом не удостоверена.

В этих27пробах median decoder greedy0,251с, beam5 0,848с; encoder0,205с.
Порядок всегда greedy→beam, batch/cold/warm/counterbalancing не исследовались.
Это локальная стоимость выбранных проб, не доказательство замедления всего FAST.

## 4. Обнаружено преждевременное смешение identity и temporal acceptance

В2:4 trace исходно отказывается от candidate5 с причиной
decaying_tail_midpoint_unproved. DSP-span33760–34660мс, midpoint34210мс.
Отказ occurs до acoustic read. После него читаются другие паузы50120/56740мс,
затем unsupported_wasl_timing;282последующие строки становятся blocked estimates.

Для диагноза выбран **каждый** unresolved declined_geometry event frozen Base12:
их2,1:4 и2:4. Reference для выбора этих новых model windows не читается.
Окно определяется правым краем прежней DSP-паузы с pre-roll200мс.
Чтения1,5/4с и дваzero-controls: ещё6encoder evaluations.

- 2:4,34460–35960: وَالَّذِينَ; полный двухсловный beam имеет q≈0,273<0,6.
- 2:4,34460–38460: وَالَّذِينَ يُؤْمِنُونَ بِمَا,
  essential quality≈0,999975; необходимые opening-условия выполнены.
- 1:4: читается إياك… следующего аята, а не مالك; оба контекста не проходят.
- Обаzero-controls не проходят.

Следовательно, плохая уверенность в midpoint не равна бесполезности речи справа.
Но она также не разрешает механически подтвердить midpoint: пример1:4 — контроль
того, что отклонённая пауза может иметь другого владельца.

Отдельный posthoc-аудит packaged reference: ближайший midpoint к2:4 отличается
на13мс. В11из23явных REVIEW_REQUIRED есть DSP-center в±500мс reference;
10из11были прочитаны,2:4 — нет. Это сравнение с benchmark cut, не физический
speech onset. Reference открыт mode=ro, SHA до/после совпал; модель его не видела.
Источник: root-locator-posthoc.json, geometry-inputs.*, geometry-results.json.

## 5. Показан локальный путь к следующей опоре

Взяты оба уже выполненных pause reads для2:4 из исходного trace. На тех же
кандидатах проверяется непосредственный следующий аят2:5; интервалы не выбирались
по reference. Два размера окна дают ещё4encoder evaluations:

- 50120–51620: أُولَى — ('اولئك','على') не доказано.
- 50120–54120: أُولَئِكَ عَلَى هُدًى — необходимые opening-условия выполнены,
  min essential quality≈0,9999.
- 56740–58240 и56740–60740: وأولئك هم… внутреннего фрагмента; opening2:5
  не подтверждается. Более длинный контекст не превращает внутреннее начало в аят.

Это конкретный кандидат для bounded sparse recovery: оставить2:4 без надёжной
точки, подтвердить следующую опору обычным валидатором и продолжить. Его полный
executor run ещё не выполнен; восстановление282меток не заявлено.
Источник: recovery-inputs.*, recovery-results.json, recovery-probe.log.

## Приоритет и проверка

План: адресное дочитывание минимальной соседней опоры → разделение read eligibility
и temporal acceptance → проверка bounded recovery → условный n-best → отдельная
точность cut/onset. Подробности и критерии в plan.md.

Всего в углублении37encoder evaluations, каждый с greedy/beam5,32реальных и
5нулевых; два реальных являются wrong-owner controls. Ни одного полного
акустического прохода. Исходные16audioSHA неизменны,3production-файла совпали
с initial source hashes. Ruff скриптов чистый. Source SHA анализа сохранены.
Пробы прямые исследовательские, не production ledger/полный бюджетный benchmark.
Общий pytest не нужен для неизменённого runtime; end-to-end приёмки ещё нет.
