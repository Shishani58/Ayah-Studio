# FAST: парный контроль sample-origin и причины расширений

Предыдущий этап дал проверяемое исправление sample origin и улучшил
экспериментальные Muaalem proofs. Этот этап сначала проверяет production
исправление на поддерживаемых моделях, затем проверяет гипотезы экономии
чтений. Pytest не запускается до общего финала.

## Гипотеза раннего отказа после одинаковой ошибки

Offline audit над retained supported33cases и Muaalem12cases нашёл7мест, где
два расширяемых окна имеют одинаковый неполный exact prefix и одинаковый
следующий ошибочный unit, при сильных unit scores. Но одно из этих мест —
55:30 — третьим чтением восстанавливает настоящий полный prefix и становится
подтверждённым. Первые окна 167620–169120 и167620–170320 пропускают `َ` в
`فَبِأَيِّ`; 167620–171820 восстанавливает его с score0,586, и общий валидатор
принимает boundary. Исходные units/scores/read IDs сохранены в
`repeated-mismatch-analysis.json`; анализ не вызывает модель повторно.

Вывод: одинаковая сильная ошибка ещё не доказывает бесполезность правого
контекста. Предложенный общий early-stop **отклонён до изменения алгоритма**.
Это decoder context effect, не отсутствие нужного слова в аудио. Такая
оптимизация потеряла бы реально существующий proof.

Исторический `fast-iterative-analysis/baseline.profile`: independent beam
2,77с из19,20с CTC observe, ASR observe129,87с из182,08с total. Это подсказка
для направления профилирования, не текущий замер и не доказательство выгоды
lazy decoder. Без свежего профиля и контроля его не вводим.

## Названия начальных букв

Штатный quran-transcript0.6.4 сохраняет source-character mapping для
`الٓمٓ`. На2/32 первая исходная `ا` соответствует ровно phones0:5 `ءَلِف`.
Остальные названия длинные и контекстно связаны: например, конечная م в лам
при ассимиляции относится к следующему mapped сегменту. Поэтому нельзя
объявить каждый character boundary универсальным концом полного названия.

Для2/32 доказана конкретная декларация полного первого названия «алиф»:
она сопоставлена со всем неизменным native4 representation и не является
произвольным обрезанием слова. Pure static run не читает аудио
(`named-letter-mappings.json/.log`). Изолированный prototype32 использует
только эту декларацию, сохраняет canonical owner floor, threshold/validator,
raw duration-bearing tempo и фактический PCM origin. Production adapter и
FAST support моделей не меняются. Свежий32 prototype дал0→18proofs,
30аятов/67reads, coverage24,55%, input ratio31,78%, max read5,5s.
Один новый reference outlier32:11 —1867ms, confidence0,698. Его не скрываем
и не считаем автоматически ошибкой распознавания:

- Proof — независимые `кафирун` (хвост10) + `куль` (целое первое слово11),
  уникальный seam, начало145078ms, read140421,375–145921,375.
- GT143211ms находится в DSP-паузе142800–145100. Сигнал в frames143180–143260
  ровно нулевой; 143500–145000 тоже peak0.0. Начало энергии145060–145100,
  RMS145080=0,011717,145100=0,15296. Поэтому перенос native onset к GT
  означал бы перенос слова в тишину, не подтверждённую фонемами.
- `32-11-outlier-proof.json`, `32-11-signal.json`, `32-11-context.wav`
  сохраняют proof, независимый DSP и слышимый участок140–147s. Audio SHA
  сверён; этот DSP-анализ не вызывает акустическую модель. Человеческое
  прослушивание не заявляется. Расхождение остаётся в raw metrics и требует
  единого решения о pause-start versus spoken-onset, не threshold fix.

Точное первое название «алиф» подтвердилось без arbitrary subword и открыло
последующие anchors. Перенос модели в production не сделан; следующее —
длинная2, preservation остальных cases и более общий declared-name scope.
С учётом prototype32 этот этап сохранил67завершённых model/surah cases,
3396строк/1115actual local calls; failed setup не включён.
