# Фаза 1 — костяк (data + персистентность + decode + код выравнивания)

## Цель / скоуп

Построить проверяемый костяк пайплайна без аудио: чтение текста Корана и
эталонов, рабочая БД с merge/автосейвом + экспорт, декод аудио, и код
forced-alignment (torch-оракул) с ленивыми импортами. e2e-прогон и GUI отложены.

## Прочитанные доки и почему

- `docs/project.md` — инварианты (6236/114, монотонность, басмала), контракт БД.
- `docs/development/python-style.md` — core/data чистый Python без PySide6/torch
  на верхнем уровне; тяжёлое — лениво.
- План `plans/...playful-marshmallow.md` — структура модулей и фаз.

## Решения

- Окружение: `uv` + Python 3.12 в `.venv` (системный 3.9 не подходит). Лёгкие
  зависимости (numpy, soundfile, imageio-ffmpeg, ruff); torch/onnxruntime/PySide6
  не ставились (не нужны для проверяемой части).
- Оркестрация воркфлоу: на каждый независимый модуль — impl-агент, затем
  отдельный review-агент **читает код** (без написания тестов) и сверяет
  инварианты; один раунд фикса при блокирующих замечаниях.
- Корректность Корана выше минимализма: добавлен `UNIQUE(sura,ayah)` и проверка
  отсутствия дублей в экспорте (last-line defense инварианта 6236).

## Проверка

- ruff: все модули чисто.
- Smoke (impl-агенты): счёт аятов 6236/114, Фатиха=7, Бакара=286; load эталона =
  6236, (1,1)=100; MERGE сохраняет verified/edited; экспорт оставляет только
  `timings`+`db_version`; decode синусоиды → 16k mono нужной длины; `core`
  импортируется без torch/PySide6.
- Ручная доп-проверка (этот сеанс): `UNIQUE` индекс блокирует дубль через API;
  guard экспорта ловит дубль и считает уникальные `(sura,ayah)`.
