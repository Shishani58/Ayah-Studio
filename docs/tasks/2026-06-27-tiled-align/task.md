# Tiled forced alignment — точность full без часа/233 ГБ на длинных сурах

## Проблема
Первый проход (генерация) на Бакъаре (~118 мин аудио) шёл ~час. Причина — не
модель, а Viterbi `core/_ctc.forced_align`: матрица обратных указателей
`T × (2L+1)`. Замер: Бакъара T≈354k кадров, L≈41k токенов → `back` = **233 ГБ**
→ своп-трэшинг. Растёт как длина². Короткие суры — единицы–сотни МБ.

Fast-режим (паузы → окна) это НЕ чинит: на длинных васл-сурах паузы перестают
быть якорями (≈30% границ — васл; остальные неоднозначны) → DP «пауза→аят»
дрейфит → срабатывают фолбэки `verify_sim`/`mean_conf` → откат в `align_surah`
(full) → снова 233 ГБ/час. См. [[fast-mode-failure-landscape]].

## Решение: тайлинг точного forced-align
`core/align_tiled.py` — `align_surah_tiled(...)`. Режут не аудио/паузы, а
**известный текст** на куски по бюджету токенов/времени; каждый кусок —
ТОЧНЫЙ forced-align в узком окне.
- **Якорь — не пауза, а точно найденная граница предыдущего куска** + темп
  (темп нужен лишь чтобы слова куска попали в окно; на уровне куска ~0.47 с
  приора с запасом хватает).
- Окно: `[граница пред. куска − 0.1с, начало следующего аята (по темпу) + pad]`.
  Правый край у начала следующего контента — иначе forced-align тянет ХВОСТ
  куска вперёд на похожее аудио (был баг: −52 с).
- 2 аята левого контекста (lead-in) + 3 аята правого контекста (впитывают
  краевой дрейф, их онсеты отбрасываются). Без правого буфера последний
  доверенный аят уезжал (~12 с).
- grow-on-edge: если последний доверенный аят у правого края — расширить окно
  (рост ОГРАНИЧЕН половиной текущего окна, иначе ранний кусок раздувался до
  размеров суры → пик памяти ~9 ГБ).
- Не дрейфит: каждый кусок заново цепляется за реальный звук (Viterbi оптимален
  внутри куска), ошибка не каскадит. Васл не нужен.
- Память на кусок ограничена (~сура-78, освобождается). Полный путь — фолбэк на
  вырожденном окне (корректность > скорость).

Проводка: режим `tiled` в `pipeline.process_surah` + `_GEN_MODES` + UI
(оба списка «точно · большие», hint, modeLabel). Full не тронут.

## Проверка (эталон Шатри, есть GT)
- **Паритет с full**: сура 112 — 0 мс; сура 78 (2 шва) — медиана 4, max 17 мс;
  78 принудительно в 9 кусков (8 швов) — max 17 мс (**дрейф по швам не копится**).
- **Бакъара (286 аятов) vs GT** (до фикса памяти): 54 куска, **20.4 мин**
  (было ~час), точность медиана 77 / p90 681 / p95 1124 / max 2154 мс,
  ≤150=67% / ≤500=87% (на уровне full, без дрейфа). Пик RSS 8.8 ГБ →
  после ограничения grow-on-edge: <ожидается ~1 ГБ, перепроверяется>.

## Осталось/возможные улучшения
- Кэш эмиссий по перекрытиям контекстов (как `align_fast.emis_cache`): сейчас
  контексты дают ~2× пере-счёт эмиссий → 20 мин. Кэш → ближе к «один проход»
  (~10–12 мин). Не сделано (минимализм; 20 мин уже 3× к часу).
