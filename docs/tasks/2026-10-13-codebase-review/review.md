### F1 · P1 · Транслитерация сдвинута относительно канонических слов

[transliteration.py:133](/Users/ayub/Developer/surah-cutter/surah_cutter/data/transliteration.py:133)
назначает строки внешнего словаря по позиции слова без согласования сегментации.
В текущем `data/word_tr_cache.json` три аята имеют меньше записей, чем канонический
текст. Во всех трёх источник объединяет `بَعۡدَ مَا`, а каноническая БД содержит
два слова. Все последующие соответствия в аяте сдвигаются.

| Аят | Канонических слов | Записей cache | Последнее слово без цели |
|---|---:|---:|---|
| 2:181 | 14 | 13 | عَلِيمٞ |
| 8:6 | 12 | 11 | يَنظُرُونَ |
| 13:37 | 20 | 19 | وَاقٖ |

Например, 2:181: `بَعۡدَ → baʿdamā`, `مَا → samiʿahu`,
`سَمِعَهُۥ → fa-innamā`, последнее слово получает `""`.
`align_ayah_words` для всех трёх аятов воспроизводимо отклоняется с
«Не все слова представлены в словаре модели», до inference. FULL без перехода
в tiled также отклоняет пустые token spans; tiled допускает перенос старта
для слова без токенов. Поэтому поведение зависит и от режима/длительности.

Нужно согласовать сегментацию при воспроизводимой сборке словаря и проверять
все 77 432 канонических слова. Проверки длины итогового массива недостаточно:
сейчас недостающая позиция уже заполнена пустой строкой. Канонический текст
изменять нельзя; ручная правка generated cache не решает воспроизводимость.

### F2 · P1 · Генерация может затереть только что сохранённую ручную правку

[project_db.py:159](/Users/ayub/Developer/surah-cutter/surah_cutter/data/project_db.py:159):
`_status()` выполняется до начала write-транзакции, затем `write_timings`
удаляет/вставляет метку и принудительно ставит `auto`. Фоновый `_GenJob`
не удерживает `_PROJECT_LOCK` при этой записи; HTTP-редактор доступен одновременно.

Воспроизведение: генератор прочитал `auto`; пользователь записал 1100 мс
со статусом `edited`; генератор продолжил и сохранил 1200 мс со статусом `auto`.
История ручной правки осталась, сама метка потеряна. Это прямое нарушение
защиты edited/verified; последовательные тесты сохранности его не ловят.

Проверять статус и выполнять merge в одной транзакции с блокировкой писателя
(например, `BEGIN IMMEDIATE`) либо использовать атомарную условную запись.
Инференс должен оставаться вне этой транзакции. Проверить реальное чередование
двух SQLite-соединений, включая смену `auto → verified`.

### F3 · P1 · Merge с ручными метками может сохранить обратный порядок аятов

[project_db.py:162](/Users/ayub/Developer/surah-cutter/surah_cutter/data/project_db.py:162)

Не исправлять это перемещением ручной границы или безусловным clamp.
Тот же контракт нужен для `set_time`, чтобы Qt/CLI не обходили HTTP-проверки.

### F4 · P2 · SSE-подключения потребляют общую очередь вместо получения копий

[server.py:498](/Users/ayub/Developer/surah-cutter/surah_cutter/webgui/server.py:498):
каждый `generate_stream` вызывает `job.q.get()` на одной очереди. Два клиента
делят события между собой. Единственный sentinel `None` завершает только один
поток; второй может бесконечно ждать. После завершившегося первого подключения
новое подключение к той же задаче также ничего не получает.

Воспроизведение создаёт два настоящих StreamingResponse: первый забирает
`done` и sentinel, для второго очередь пуста. Reconnect/reload и браузерный
fallback делают это практическим сценарием. При потере соединения UI сбрасывает
локальное состояние, хотя вычисление может продолжаться.

Нужны независимые подписки или журнал событий с курсорами, сохранённый конечный
статус и возможность получить текущую задачу после reload. Отключение подписчика
должно освобождать ожидание; ограничить накопление событий без подписчиков.

## Производительность и жизненный цикл: риски, а не измеренные дефекты

- `decode.duration_ms()` декодирует весь файл. Пословные чтения последнего
  аята и экран всех слов вызывают его снова; для длинных записей это повторные
  CPU/I/O и большие PCM allocations. Кэшировать длительность по идентичности
  файла или получить её при уже выполненном decode; точный PCM duration сохранить
  источником истины для границ.
- `generate_emissions` заранее создаёт все input windows через `np.stack`,
  несмотря на batch=1. Tiled держит emissions всей суры. Это разрешено для FULL,
  но память не ограничивается одной акустической порцией. Измерить peak RSS на
  длинных сурах перед оптимизацией.
- `_ctc.forced_align` хранит int64 backpointer для каждой frame/state пары;
  banded-путь уже хранит uint8 choice. Хранение только выбора predecessor даёт
  возможность уменьшить backtrace-память примерно в 8 раз без изменения
  алгоритмической сложности; это требует проверки идентичности paths/scores.
- `RuntimeEmitter._receive()` ожидает `readline()` без timeout. Отмена генерации
  убивает child, но синхронный выбор/probe модели не имеет такого cancellation
  scope. Зависший child способен удержать runtime и project locks. Нужен
  ограниченный жизненный цикл и понятная ошибка, без подстановки другой модели.
- Разрешённые методы `ProjectDB.write_timings(force=True)` обходят защиту manual
  и не создают историю такого сброса. Активных вызывающих мест в проверенных
  продуктовых путях нет; не подключать этот обход к обычной перегенерации.
- `_PACKAGES` фиксирует прямые runtime-зависимости, но устанавливает транзитивные
  зависимости заново без отдельного lock. Сохранённые версии помогают аудиту,
  однако не гарантируют повторную сборку того же окружения.

5. После этих регрессий — небольшие извлечения общих CTC/текстовых операций,
   затем фаз FAST; изменения сверять с текущими trace и контрактом локальных чтений.
