# Fast alignment: block DP for pause-backed openings

## Цель

Начать исправление fast-only алгоритма на основе выводов
`docs/tasks/2026-07-01-fast-alignment-lessons/lessons.md`: границы аятов должны
выбираться прежде всего по достоверным паузам, а проблемные repeated-opening
участки должны решаться локальным order-preserving сопоставлением блока, не
жадными одиночными правками.

## Скоуп

- Только fast alignment.
- Не трогать full/accurate режим.
- Не менять формат данных и БД.
- Первый шаг: заменить симптоматический greedy opening repair на локальное
  сопоставление нескольких соседних аятов с pause-кандидатами.

## Решения

- Основной сигнал: порядок пауз и prefix evidence; fuzzy similarity только
  вторична.
- Wasl допустим только когда в локальном блоке нет достоверного pause-backed
  назначения.
- Регрессионный тест сначала сделать на чистом helper-уровне без ONNX/аудио,
  затем прогонять focused pytest.
- Проверенный отрицательный результат: широкий `earliest coherent pause block`
  для всех непривязанных границ ухудшает `037`, потому что начинает считать
  внутренние остановки отдельными стартами аятов. Значит следующий шаг — не
  "брать самые ранние паузы", а block-DP с явным состоянием `ayah-start` vs
  `internal-stop` и/или декодом всего соединённого участка.
- Для `120–129` полезен не широкий block recovery, а запрет позднему
  `weak_pause_recovery` перепрыгивать через уже плотную последовательность
  достоверных пауз. Такой guard оставляет участок на fallback/interpolation и
  убирает самый большой каскад.
- Для `078–087` полезен section-decode: серия `wasl` + низко-достоверных
  `pause_fallback`/`weak_pause_recovery` между двумя нормальными якорями должна
  выравниваться цельным `align_slice`, а не уточняться по одной слабой паузе.
- Для длинного аята внутри section-repair нужен узкий internal-stop guard:
  если сырой onset попал рядом с `micro-tempo`, а перед ним есть сильная `dsp`
  пауза, которая лучше объясняет длительность предыдущего текстового span,
  старт переносится к этой сильной паузе. Это сняло ошибку `037:087`.
- Для длинной выбранной паузы с коротким фрагментом речи до неё и длинным
  фрагментом после неё нельзя автоматически брать `pause.end_ms`: это может быть
  внутренняя остановка внутри текущего аята. Перед таким сдвигом алгоритм ищет
  предыдущую свободную сильную `dsp` паузу, которая существенно лучше объясняет
  длительность текста от предыдущего старта. Это сняло основной промах
  `037:100`.
- Если weak `micro-tempo`-граница дала ранний pause-backed старт, но repair
  уверенно нашёл первое слово на следующей реальной `dsp/weak-dsp` паузе, такой
  forward repair можно принять только при хорошей текстовой геометрии между
  соседними якорями. Это сняло основной промах `037:051`.
- Если выбранная поздняя `dsp`-пауза имеет признаки внутренней остановки, а
  перед ней есть свободная `dsp` пауза, fast может сделать локальный decode
  участка между соседними аятами и принять перенос только если первое слово
  найдено рядом с этой предыдущей паузой. Это сняло `037:055`.
- Phase 2b не должен заменять pause-backed границу на off-grid предсказание,
  когда repair decode не набрал `conf_thresh`; это защищает соседние аяты после
  локального section-decode. Это удержало `037:060` от ложного сдвига.
- Внутри `section-repair` CTC может поставить onset в самый конец длинной
  `dsp` pause shelf. Если перед этим не сработал `micro-tempo` internal-stop
  guard, такой onset можно перенести к началу этой же длинной паузы только для
  tail-of-shelf случая. Это сняло `037:083`; общий snap всех попаданий внутрь
  длинных пауз был отклонён.
- Для обычного pause-backed выбора тоже нужен строгий timing-point: если
  доверенная длинная `dsp` pause shelf имеет почти нулевую речь до неё и очень
  короткую речь после неё, старт аята — начало shelf, а не центр. Это сняло
  `037:022`.
- Если слабая `micro-tempo` граница стоит сразу после свободной сильной `dsp`
  паузы, нужно брать эту `dsp` паузу, а не сдвигать micro-point вперёд. Это
  сняло `037:023`.
- Если длинная `dsp` pause shelf идёт после завершённой речи и до следующей речи
  фактически тишина, старт аята должен быть началом shelf, а не центром. Это
  сняло `037:058` и `037:061`.
- Если длинная `dsp` pause shelf имеет хорошее объяснение длиной текста с обеих
  сторон (`prev/next speech-span quality`) и выбрана через `pause_fallback`, это
  не внутренняя остановка и не repeated-opening steal; старт берётся от начала
  shelf. Это сняло основной промах `037:101` и улучшило `037:145`.
- Для repeated-opening внутри длинной `dsp` shelf near-edge refine можно принять
  только как left-edge proof: onset должен быть внутри той же shelf, до центра,
  и иметь `conf >= conf_reliable`. Это не глобальное разрешение near-edge; оно
  сняло `037:067`, но не тронуло `037:068`, где left-edge варианты
  низкоуверенные.
- Средние `dsp` shelf до `1.3s` при нормальном sim считаются compact и берут
  центр, а не левый край. Это исправило `037:088`; эксперимент с env-порогом
  показал улучшение p90/p95 без регрессии на `080/083`.
