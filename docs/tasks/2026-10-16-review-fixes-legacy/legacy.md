# Аудит legacy

Проверено 2026-10-16 по текущей рабочей папке, включая исходные незакоммиченные
файлы. Поиск импортов через AST дополнен поиском имён и просмотром callers:
импортированные aliases, entrypoints и динамические импорты не считаются мёртвыми
только из-за отсутствия обычного вызова.

## Исправляется в этой задаче

- Режим `auto`: скрыт в GUI, но оставался в pipeline, CLI, API и Qt default.
  Удаляется как исполняемый режим; default — `full`. Ветвь автоматического
  применения reference по имени чтеца удаляется вместе с ним.
- Старые ожидания FAST checker: прежние `unresolved_local` / `match_action`
  не соответствовали текущим `estimate` / `first_onset` / `wasl` в executor.
  Проверка переводится на текущий контракт с сохранением проверок доказательств.
- `auto` в `review_meta.status` остаётся действующим статусом автоматической
  метки, а не режимом расчёта. Исторические trace/source с `auto_mode` читаются.

## Нужен продуктовый выбор, это не мёртвый код

- `gui/`: прежний Qt-интерфейс, 1231 строка реализации, extra `qt` и команда
  `surah-cutter-gui-qt` в pyproject. Проверяется отдельными тестами. Можно убрать
  при официальном прекращении поддержки Qt; сейчас entrypoint существует.
- `hybrid` и отдельный `fingerprint`: не показаны в основном меню, но доступны
  в CLI (hybrid также API); это рабочие альтернативы. Их удаление меняет API.
- `experimental_fast` / `--experimental`: compatibility aliases общего FAST,
  а не отдельный экспериментальный алгоритм. Можно отменить вместе с обновлением
  инструментов `bench_fast_models.py` и вызывающих тестов.
- Старые имена `surah-cutter*`: алиасы команд для текущего Ayah Studio, не
  отдельные реализации. Удаление ломает привычные команды/скрипты.

## Что сохранить

- `data/references` и `data/references.py`: эталоны нужны benchmark/eval, даже
  после удаления shortcut, который применял их к записи по имени чтеца.
- `data/alignment_runs.py`: legacy reader открывает старую историю расчётов;
  удаление затронет существующие проекты.
- `core/align_fast.py`: маленькая публичная точка входа, которую вызывают
  pipeline, API и инструменты. Это не вторая реализация FAST.
- `core/full_boundary.py`, `full_pause_center.py`, `full_signal.py`: текущая
  цепочка FULL; схожие названия не означают дублирования.
- `style.css` и `studio.css`: оба подключены `index.html`, второй переопределяет
  оформление. Возможна консолидация с визуальной проверкой, но не слепое удаление.
- Torch/oracle, export tools и runtime locks: используются подготовкой моделей,
  проверкой соответствия и отдельными runtime; отсутствие их в основном GUI
  не означает отсутствия назначения.
- Исторические `docs/tasks`: evidence предыдущих запусков, не runtime-модули.

## Рекомендуемый порядок очистки

1. Удалить подтверждённые неиспользуемые функции и старый этап FULL v8 узкой
   правкой, сохранив текущий v9 signal-only и результаты аудиотестов.
2. Убрать старый fingerprint refinement и auto-only repair/lag.
3. Отдельно решить поддержку Qt и скрытых CLI режимов.
4. Отменять compatibility aliases только вместе с обновлением callers.

Массовая перестройка каталогов и удаление эталонных данных для этого не нужны.
