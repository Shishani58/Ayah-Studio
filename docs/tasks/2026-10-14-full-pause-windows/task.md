# FULL: участки по паузам и параллельное чтение

## Цель и scope

Проверить предложение пользователя: выбирать границы акустических участков FULL
по DSP-паузам, выполнять независимые ONNX-вызовы параллельно, соединять
центральные emissions перед прежним CTC. Без отдельных аудиофайлов, изменений
канонического текста и записи пользовательских БД.

Первый этап — воспроизводимый opt-in эксперимент Quran Phonetics INT8 на
локальном Шатри; обычный FULL/FAST и выбор модели не меняются до замеров.

## Прочитано

- `AGENTS.md`, `CLAUDE.md`, `/Users/ayub/.codex/RTK.md`: ограничения и sync
  (оба проектных файла идентичны).
- `docs/project.md`: FULL, глобальная нормализация, один участок на INT8-вызов,
  bounded CTC, изоляция FAST.
- `docs/STATUS.md`: предыдущие проверки границ и ограниченность старых замеров.
- `core/emissions.py`, `core/align.py`, `core/candidates.py`, `core/cancellation.py`:
  кадры, контекст, DSP-паузы, отмена native inference.
- `tests/test_emissions.py`, `tests/test_alignment_audio.py`, предыдущий
  reliability benchmark: эталон и доступные локальные данные.

## Решения

- Граница около целевой длины, предпочтительно центр DSP-паузы. Без паузы —
  ограниченный участок с перекрытием; тишина не считается границей аята.
- Общая нормализация записи, сетка 20 мс, контекст 2 с, один участок на вызов.
- Ограниченная очередь; порядок результатов равен порядку записи, независимо
  от порядка завершения. Отмена передаётся рабочим потокам.
- Замеры отдельно DSP/inference/CTC/load, peak RSS; флаги, хэши, реальные
  интервалы, все границы и ошибки против независимого эталона в JSON.
- Сравнить fixed30 и pause10/20/30, workers1/2/4; параллельный результат должен
  совпадать с последовательным при одинаковых участках.

## Расширенная проверка и решение

Шатри 78–114, 37 сур / 564 аята, CPU ONNX Runtime 1.27.0; прогрев до замера.
FULL здесь = DSP/нормализация/inference + штатный CTC/проверки; decode/load
измерены отдельно и не входят в FULL. Peak RSS — весь процесс случая, включая
загрузку модели; это high-water mark, а не память одного окна.

| Метрика | Fixed30, workers1, штатный pool | Pause20, workers2, штатный pool |
| --- | ---: | ---: |
| FULL | 271.50 с | 212.48 с |
| Акустическая фаза с DSP | 264.26 с | 204.40 с |
| CTC/проверки | 7.24 с | 8.08 с |
| Peak RSS | 1119.95 MiB | 1503.34 MiB |
| Median / p95 / max ошибки | 58 / 269 / 1196 мс | 57.5 / 253.4 / 1196 мс |
| Ошибки >500 мс | 15 | 15 |
| Ошибки >500 мс без флага ревью | 3 | 4 |

В этом прогоне время уменьшилось на 21.74% (1.28×), peak RSS вырос на 34.23%.
Новых ошибок >500 мс нет: совпадает и их набор, не только количество.
Max изменение границы — 420 мс (улучшение); max ухудшение абсолютной ошибки —
100 мс. 113 границ рядом со стыками: max ошибка 1088 мс до/после.
121 разрез по паузе, 2 разреза без паузы с контекстом. Число/порядок аятов
правильны во всех случаях; исключений выравнивания нет.

**Не включать по умолчанию:** у 83:10 (+825 мс к эталону) и 95:8 (+840 мс)
исчез флаг ревью. Эти ошибки были и раньше, но предупреждения стали слабее.
79:26, напротив, получил флаг. Всего флагов 403→354; их уменьшение само по себе
не означает повышение надёжности. До штатного включения требуется отдельная
проверка/калибровка первого слова и предупреждений для новых акустических окон.
Штатные FULL/FAST, настройки и writer не изменены.

Две повторные чередующиеся пары на 78/80/98/112/114:
69.98→48.15 с и 71.06→45.05 с (−31.20% / −36.60%). Все emissions каждого
варианта воспроизвелись побайтово. Время заметно зависит от фоновой нагрузки

чтецу/компьютеру. 1–77, другие чтецы, Whisper/другие адаптеры, GUI/.app/Windows
не проверены этим экспериментом.
