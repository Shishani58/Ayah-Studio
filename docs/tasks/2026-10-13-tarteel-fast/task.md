# Tarteel Base: локальный FAST и сравнение 37 сур

Цель: подключить собственные веса Base к FAST и сравнить с Quran Phonetics
INT8 на Шатри 78–114 (564 аята). Только DSP/VAD-паузы и небольшие различающие
фразы; без полного чтения, скрытого FULL или tiled.

Прочитаны AGENTS/CLAUDE, RTK, docs/project.md (FAST и модели), STATUS,
fast-local-implementation/task.md и benchmark.py,
model-shortlist/fast-model-selection.md, tarteel-models/task.md;
fast_reads, pipeline, worker/runtime, API guards.

Решения: отдельный Whisper pause/sequence adapter, жёсткий бюджет ≤6 с,
union≤65%, input≤200%. Независимая локальная фраза сравнивается с известным
началом аята. Пауза задаёт центр границы; отсутствие доказательств —
confidence=0 и ревью. Распознанный текст не заменяет Коран. Lag=0,
без подгонки по эталону. Сравнение на одном initial DSP/VAD наборе;
эталон только после inference. Чужие изменения сохранить, без коммитов.

Чек-лист: адаптер/RPC и trace; режим CLI/API/UI; safeguards/tests;
37 сур, ошибки/ревью/latency/прочитанный вход; docs и справка.

Блокеры: пока нет; качество измеряется, основная модель не меняется автоматически.

## Реализация

- `align_fast_whisper.py` — отдельный Base pause/ASR/sequence адаптер.
  Известное начало аята берётся из проверенного Imlaey; QPC не изменяется.
  Минимальный различающий префикс — от 2 до 6 ортографических слов (для
  однословного аята допустимо одно длинное уникальное слово). N-gram-проверка
  учитывает повторы и внутри аятов, а не только похожие начала.
- Сначала DSP/VAD, затем 1.3 с речи + до 200 мс pre-roll. Увеличение до 2.5/4 с
  разрешено только при распознанном правдоподобном, неполном/неоднозначном
  префиксе. Посторонняя фраза не увеличивает окно. Все минимальные чтения
  выполняются раньше расширений, чтобы оставить бюджет поздним аятам.
- Константы зафиксированы до корпусной оценки: similarity≥0.9, margin≥0.12,
  token confidence≥0.6; нужен полный различающий префикс и EOS, не truncated
  decode. Greedy, Arabic/transcribe, max_new_tokens=64, use_cache=True,
  batch=1, CPU, 4 потока. Source содержит режим/версию/флаги/версии runtime.
  Фонетические SC_FAST-настройки не управляют параметрами Base.
- Общий `_permit` в `fast_reads.py` сохраняет прежний CTC budget и защищает
  ASR: ≤6 с, union≤65%, суммарный вход≤200%, целая запись запрещена даже если
  она короче 6 с. Cache ASR — только точное совпадение окна; новый срез
  требует нового распознавания и учёта. Дополнительные guards в RPC и worker.
- Worker получает только вырезанный PCM; независимый ASR подтверждает
  известный аят, не заменяет Коран. В FAST нет `whisper_align`, teacher forcing,
  целого акустического прохода или FULL/tiled fallback. Стандартное Whisper
  padding до 30 с — нули, а не остальное аудио; оно увеличивает вычислительную
  стоимость коротких вызовов, но не прочитанное аудио.
- Выбирается монотонный каркас подтверждённых пауз/аятов. Пауза даёт центр
  границы. Отсутствующие/слабые/неразличённые границы — interpolated structural
  prior с confidence=0 и review_required_ayahs. Confidence не калиброван как
  вероятность точного тайм-кода. Длинный wasl не читается целиком.
- FAST доступен для Base в pipeline, API настроек/генерации/debug и меню.
  Выбор Base сохраняет явно выбранный fast/full/words/tiled; auto/hybrid
  недоступны для Base. Для words отсутствующие аятные границы используют
  поддерживаемый FAST, сами слова — прежний отдельный расчёт. Внешние аятные
  клипы в Base FAST пока отклоняются до inference, без молчаливого игнорирования.
  Quran Phonetics остаётся основной. Tiny и другие Whisper FAST не поддерживают.

## Сравнение 78–114

37 одинаковых MP3, 564 канонических аята, 3184.48 с записи. Один предварительно
вычисленный набор DSP/VAD `PauseDecision` передан обоим адаптерам. Phonetics
сохраняет свои последующие micro/DSP-проверки; адаптеры не объявляются одним
алгоритмом. `bench_fast_models.py` читает timing reference только после
завершения **обоих** inference-прогонов. Эталон не участвует в выборе пауз,
целей, времени или thresholds. Параметры не подгонялись по корпусным ошибкам.
Другие акустические тесты параллельно не запускались.

| Метрика | Quran Phonetics INT8 | Tarteel Base |
|---|---:|---:|
| median, мс | 73.5 | 67.5 |
| p95, мс | 4465.85 | 1628.2 |
| max, мс | 26762 | 6062 |
| ошибки >500 мс | 107 / 564 | 64 / 564 |
| для ревью | 288 / 564 | 153 / 564 |
| ошибки >500 без ревью | 6 / 276 | 9 / 411 |
| DSP + inference/matcher, с | 136.32 | 516.41 |
| только inference/matcher, с | 133.07 | 513.16 |
| load/probe, с | 0.17 | 5.34 |
| decode, с (общий) | 3.77 | 3.77 |
| предварительный DSP/VAD, с (общий) | 3.24 | 3.24 |
| вызовы модели | 1650 | 1104 |
| объединённое покрытие корпуса | 60.87% | 46.44% |
| суммарный вход, включая повторы | 140.37% | 70.98% |
| максимальный отдельный вход | 6 с | 4.2 с |
| максимальное покрытие одной суры | 65% | 57.01% |

У Base грубых ошибок на 40% меньше, ревью на 47% меньше, p95 лучше на 64%.
Она примерно в 3.8 раза медленнее на CPU. Среди границ без ревью доля ошибок
>500 мс примерно 2.2% у обеих моделей; поэтому 9 против 6 нельзя трактовать
без учёта разного количества подтверждённых границ. Max такой ошибки Base
903 мс, Phonetics 2955 мс. Общие цифры включают все priors, а не только удачные
подтверждения. Base исправила 80 грубых ошибок основной модели, но дала 37
новых; 27 грубых ошибок общие. Пары и отдельные срезы — analysis.json.

Контрольный результат Phonetics воспроизвёл прежние median/p95/max, 107
ошибок и 288 ревью; новый таймер отделяет подготовительные этапы. Усиленная
проверка обнаружила priors 82:18=113784 и 82:19=121115 за концом аудио,
с confidence=0. Они сохранены в sequence_violations; алгоритм контрольной
модели ради сравнения не менялся. Первый запуск benchmark остановился на
этой проверке; его 4 суры сохранены в initial-baseline-partial.json. Финальный
аудит не скрывает этот дефект и включает обе метки в ошибки. У Base нарушений
границ аудио нет. Полный порядок/число аятов и бюджет чтений соблюдены у обеих.

В Base нет denied reads на этом наборе; Phonetics — 1299 отказов бюджета.
Отказы не приводят к скрытому чтению. Все фактические абсолютные интервалы,
frames, причины расширений, распознанные фразы, confidence и метки ревью —
comparison.json. Summary содержит initial pause SHA/решения, исходники,
audio/reference/canonical SHA. Pinned Base revision, хеш каждого файла,
processor/generation metadata и окружение — reproducibility.json.

Решение: Base подключена как экспериментальный локальный FAST с улучшенным
общим хвостом на этих записях, но не заменяет основную модель. Её скорость,
оставшиеся неподтверждённые wasl и ошибки подтверждённых центров требуют
внимательного ревью. Другие чтецы/1–77 не проверены; корпус не является
независимым доказательством переноса. Tarteel не раскрывает состав обучающих
данных в карточке. Некалиброванные attention heads относятся к FULL,
в этом FAST они не выбирают границы.
