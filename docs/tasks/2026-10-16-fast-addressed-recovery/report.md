# FAST sparse-14: следующий DSP-кандидат

Код перенесён в рабочую `main` без коммита. Проверки качества, стоимости и
API/persistence завершены. Покрытие выросло; ориентир стоимости p95≤2× не пройден.

## Что перенесено

`fast_executor.py` сохраняет предыдущую sparse-13 и добавляет для установленной
Tarteel Base одну следующую DSP-паузу после неудачи кандидатов непустого tempo
region. Требуется свободное место в прежнем cap8, прежний физический lookahead,
радиус новой паузы≤500мс и обычный независимый полный текстовый proof. Новая
гипотеза может доказать текущий или максимум два следующих аята. Ранее услышанное
сильное неполное начало продолжает запрещать поздний повтор.

Пропущенные аяты остаются review estimates. Стационарная тишина не доказывает
точное время широкого midpoint: в новой цепочке radius>500мс остаётся review.
Owner/time сохраняются в `IDENTITY_ONLY`, замена времени не выводится.
Фильтр выполняется до прежнего weak-prefix фильтра; body→head retry сохраняет
тот же origin. Новый VERSION меняет fingerprint/resume identity.

Бюджеты6s/65%/200%, cache32MiB, Tiny/CTC и формат SQLite не менялись. Модели не
скачивались, активная модель/настройки пользователя не переключались. Сторонние
изменения pipeline, FULL, model store, ProjectDB и GUI сохранены.

## Отдельный вклад относительно другого чата

Baseline — уже улучшенная F13, а не git HEAD sparse-12. Актуальный F13 SHA:
`4ec2127ff87cdf9da4d6e06e15381e47161683be829d6e7d2b50e6f7c15d3469`.
Свежая проверка current2/80 дала те же времена, owners и actual PCM dispatches,
что frozen A. Предыдущий прирост46+4 принадлежит прошлому переносу.
`composition-invariant.json`:19 прежних definitions, включая Policy и F13
фильтры, сохранены AST-идентично. Добавлены один helper и узкие ветки executor/
validator. Собственная дельта F13→F14 — `candidate.patch`; чужие изменения не
откатывались. Нынешние decode/candidates/readers/adapters/runtime/worker совпадают
с проверенным snapshot; изменения model_store/pipeline отдельно просмотрены.

## Воспроизводимость и характер измерений

- A-wide — завершённый fresh Base114. BS-wide остановлен после42 записей,
  это partial отвергнутого прототипа, не completed114.
- Минимальная абляция SF85 записей исполнила весь executor на независимо
  полученных exact-PCM observations A/BS. Недостающий crop приводит к явному
  отказу replay, без ближайшего окна или подстановки текста.
- Из29 записей с пропусками две уже имели fresh SF runs; для остальных27 PF
  исполнил hybrid executor:384 недостающих crop прочитаны реальной Base,
  остальные897 logical calls взяты только по точному PCM SHA/длине. Для каждого
  чтения сохранены source/read_id либо actual fresh-dispatch index. Все1281
  logical inputs учитываются в обычных бюджете/ledger; это не whole fresh27.
- Итоговый PF исполнил114 записей полным exact-PCM replay всех потребованных
  независимых observations. Паузы, PCM, текст, runtime/assets и policy совпадают
  с A; окон/owners/порогов по reference не выбирали. Нулевые/чужие записи и
  известные внутренние начала отвергнуты отдельной fresh проверкой Base.
- Все27 межчтецовых пар сняты fresh. PF publication/provenance композиция
  дополнительно исполнялась на точных PCM этих записей. Reference открывается
  readonly после предсказаний. Hashes и команды сохранены в JSON sidecars.
- `A-source.zip`, `PF-source.zip`, manifests и `snapshot-paths.json` фиксируют
  источники; веса/config/tokenizer/runtime/Silero/PCM/DSP identities находятся
  в run_snapshot. Тестовый mmap лишь использует ранее декодированный PCM с
  совпадающим SHA. Production такого внешнего observation cache не содержит.
  Независимый ASR не получает ожидаемый текст аята; одинаковые PCM и runtime
  допускают сравнение правил executor на одном и том же наблюдении.

## Проверки и ограничения

- Общий pytest текущего рабочего checkout:982 passed/10 skipped,21,30с.
- 11 новых regression cases; отдельный PF core run205 passed. Красный/зелёный
  пример подтверждает потерю wide-review при обратном порядке фильтров.
- Scoped Ruff чистый. Шесть несовпадений раннего snapshot с новыми pipeline/
  ProjectDB tests устранены использованием текущих файлов, без отката чужих
  изменений; общий production run прошёл.
- Реальный API→pipeline→FAST→writer smoke на временном проекте80:42строки,
  все auto times и actual PCM dispatches совпали с PF; edited/verified сохранили
  время и полный review metadata. Старый resume key инвалидирован. Модель/DSP/
  writer реальные; замоканы только состояние тестового проекта, сохранение
  глобальных настроек, синхронный запуск job и сбор событий. Первый валидатор
  ожидал старый JSON root, затем исправлен под текущую обёртку `trace` и полный
  реальный smoke повторён. `application-smoke.json` и raw diagnostic рядом.
- Final audit:47 исходных data DB,141 audio,4 reference DB,10 Base assets и
  Silero сохранили hashes. AGENTS/CLAUDE побайтово идентичны. Production SHA
  совпадает с измеренным PF. Пользовательские проекты не менялись; записаны
  только одноразовые smoke fixtures. `final-audit.json`.
- Physical onset/cut labels и слушательская приёмка отсутствуют. Confidence
  остаётся minimum independent token support, а не калиброванной вероятностью
  точного времени. Даже сильная identity не делает DSP midpoint точным onset.

Для уже открытого GUI нужен перезапуск, чтобы загрузить sparse-14. Существующие
пользовательские auto метки сами не пересчитывались; последующий FAST сохраняет
обычную защиту edited/verified.
