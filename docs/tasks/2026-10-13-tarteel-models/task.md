.bin читается явно torch.load(weights_only=True, map_location=cpu); strict
state_dict. Старый checkpoint не содержит proj_out.weight: только при
подтверждённой tied-связи он берётся из собственного decoder embedding.
Первоначальный отказ сохранён в tiny-initial-load-failure.json.

Generation config/alignment heads у Tarteel отсутствуют. Использованы явно
зафиксированные исходные OpenAI Tiny/Base configs, включая SHA/revision
(см. каталог и *-upstream-generation.json). Веса остаются Tarteel; heads
OpenAI не калиброваны для Tarteel — это экспериментальная совместимость,
а не заявленная авторами точность границ. Encoder/head probe проверяет
конечные logits и выбранные decoder cross-attention, без хранения encoder
attention всей записи. Runtime: Python 3.11, Torch 2.8.0, Transformers 4.57.3,
CPU ARM64, 4 потока; окружение/версии и источники сохранены в JSON.

Tarteel требует огласовки: target-probe.json сравнивает одинаковые четыре
слова первых аятов 112/114. Plain даёт вероятности вплоть до 3e-11; vocalized
— около 0.75–1.0. Используется существующий вспомогательный Imlaey, без
правок QPC. Старый tokenizer имеет 50364 текстовых/служебных ID; ещё 1501
неявный timestamp ID доводят голову до 51865. Проверка tokenizer-validation
проверяет encode/decode всех 77432 слов, диапазон ID, mels и heads.

FULL: известный текст → teacher forcing → attention DTW, lag=0. ASR только
находит канонический диапазон длинного окна. Окно начинается с 30 с; лишь
при конкретном переполнении token budget уменьшается до 20/10 с, заново
проверяются опоры. Текст не обрезается. Недостаточные опоры/прогресс вызывают
отказ. Постоянное 20-секундное окно ухудшило короткие записи и отклонено.
Промежуточные plain/30s/20s отчёты сохранены; финальный — validation.json.
Параллельные первые plain-эксперименты не используются для выводов о скорости.

## Локальный опыт и FAST

local_probe.py сначала DSP находит паузы без эталона, выбирает три редких
паузы на каждую суру (начало/середина/конец списка), читает 1.3 с речи +
до 0.2 с паузы. Только неподтверждённая фраза расширяется до 3 с речи;
не более 3.2 с входа за вызов. ASR-фраза сравнивается с двумя начальными
словами каждого аята, similarity≥0.8 и margin≥0.2; это эвристика идентичности,
не калиброванный confidence тайм-кода. Reference читается после inference
для оценки. Реальные интервалы, причины расширения и вход/покрытие в
*-local.json. Полного прохода/последовательного покрытия/скрытого FULL нет.

Обе модели подтвердили 5/9 выбранных пауз, неверных подтверждений на этом
маленьком наборе нет. Часть пауз 78 внутри аята, включая последний участок
далеко от его старта. На 112 короткие фразы/повторы остаются неоднозначными.
По 15 реальных вызовов; union coverage на 114/112/78 — 17.94/29.04/3.44%.
Inference Tiny 2.95 с, Base 6.24 с за все три записи (отдельно от load/DSP/decode).
Это распознавание редких локальных фраз, без полного поиска всех границ:
median/p95/max FAST здесь не измерены. Показатели действующего FAST на
37 сурах (73.5/4465.85 мс, 107 ошибок >500 мс и 288 ревью) не сопоставимы
с этим опытом. WER 7.0535/5.7544 из карточек не является точностью таймингов.

Решение: Base оставить дополнительной экспериментальной моделью; Tiny
оставить для лёгких локальных экспериментов, но не рекомендовать для
надёжной разметки длинных сур. Основную INT8 не заменять. Для FAST обеим
нужны полноценный pause/sequence matcher, ограничения чтений, локальная
проверка начала и сравнение на корпусе/других чтецах. FAST для обеих явно
недоступен, переход в FULL не выполняется.
