# Итог серии улучшений FAST

Изменения внесены после разбора причин и сравнений на сохранённых исходниках.
Прогоны использовали документированный набор сур: 1, 2, 32, 55, 59, 65, 73,
77, 79, 80, 98, 112. Фактические акустические вызовы и версии исходников
сохранены в отчётах отдельных попыток. Канонический текст и пользовательские
БД не редактировались; коммитов и push нет.

## Принятые изменения

- `surah_cutter/core/candidates.py`: RMS всей записи считается один раз,
  а не заново для каждой паузы. Свежий DSP-корпус: 1697 решений совпали точно;
  время этой фазы 37,955 → 1,253 с, на суре 2 — 36,407 → 0,568 с.
  Это ускорение DSP, а не обещание такого же ускорения модели.
- `surah_cutter/core/fast_adapters.py`: исходное написание выбранных BPE-токенов
  сохраняется до нормализации. Обычное «ألم» больше не превращается ошибочно
  в названия букв «الف لام ميم». Свежие 96 случаев: Base 114 → 130 подтверждений,
  +16 с ошибками 10–447 мс; прежние подтверждения не потеряны и не изменены.
  Остальные три модели дали те же строки и последовательности вызовов.
- `surah_cutter/core/fast_executor.py`: предварительная проверка target перед
  конкурентами, ограниченная следующая DSP-пауза при пустом ASR tempo region,
  sample-rounded начало аудио для native offsets, отклонение сильного
  противоречащего previous-body и локальная перепроверка границы ASR-слова.
  Последняя разрешена только независимым сильным body cue и подтверждает
  границу лишь новым полным opening proof с прежним порогом 0,6.
  Свежие 96 случаев этого последнего изменения: Tiny 84 → 87, новые 98:5/6/7
  с ошибками 78/12/44 мс; прочие три модели совпали точно. Потерь прежних
  подтверждений и новых ошибок свыше 500 мс нет в обоих парных корпусах.
- `tools/bench_fast_models.py`: подсчёт реальных вызовов по семейству модели;
  наличие метода recognize_local само по себе больше не определяет тип модели.
- Подготовлены регрессии по этим причинам и исправлен sampled-onset fixture:
  исходные числа округлялись одинаково и не проверяли ошибку sample offset.

Прирост покрытия требует дополнительных полезных чтений: Base 273 → 326,
Tiny в последнем парном корпусе 217 → 231. Рост точности не объявлен
ускорением нейросети. DSP-оптимизация сохраняет результаты и входы моделей.

## Что сознательно не перенесено

- ASR body-future и Muaalem прототипы: дают дополнительные anchors, но пока
  сохраняют временные выбросы; production support моделей не расширен.
- Общая замена DSP-midpoint на VAD-midpoint: помогает 79:26, но ухудшает
  1:2 и 73:20; на 77:25 зависит от контекста. Стабильность VAD не доказывает
  правильность временной границы. Ошибка Base 79:26 +508 мс остаётся открытой.
- Склеивание ASR-слов на Tiny 77:7: два свежих локальных окна исправляют
  продолжение, но сохраняют «إن ما» вместо «إنما». Без симметричной проверки
  владельцев и отрицательных случаев нормализация не добавлена.
- Tiny 79:20: модельная уверенность на том же аудио существенно ниже Base;
  увеличение контекста само по себе не дало полного доказательства.

FAST по-прежнему делает только локальные акустические чтения через ledger,
с лимитами 6 с на окно, 65% объединённого покрытия и 200% суммарного входа.
Полный DSP/VAD не заменяет доказательство текста. FULL fallback не включён.
Результаты по одному чтецу не объявлены доказательством для всех чтецов.

## Финальная проверка

Единственный общий финальный запуск тестов этой серии:
`.venv/bin/python -m pytest -q` — **683 passed, 8 skipped in 9.94s**, exit 0.
Полный журнал: [pytest.log](pytest.log).
Проверяется вся текущая совместная рабочая копия, включая смежные FULL/UI
изменения; их результаты не приписываются FAST.
Ruff изменённых FAST-файлов и регрессий — clean, [ruff.log](ruff.log).
`git diff --check` — clean; AGENTS.md и CLAUDE.md побайтово идентичны.
После этого запуска production и тестовый код не менялся.
