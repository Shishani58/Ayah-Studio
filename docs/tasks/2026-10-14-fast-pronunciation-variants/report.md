# FAST: длительность фонем, различимость аятов и прогноз окна

Эксперименты используют Muaalem только через локальный диагностический адаптер.
Модель не активирована в production FAST. Текст, пользовательские БД, веса и
выбранная модель не менялись. Pytest не запускался: пользователь разрешил его
только в общем финале.
За этот этап сохранены 33 завершённых model/surah случая, 1604 строки,
1392 фактических локальных вызова (`attempt-totals.json`). Неуспешные и
отменённые попытки описаны отдельно и не включены в эти числа.

## Последовательность и причины

1. Штатный quran-transcript 0.6.4 с `madd_aared_len=4` воспроизвёл все прежние
   mappings на 12 сурах. Варианты 2/6 получены из того же канонического текста,
   без акустического прохода. Глобальная смена длительности не подходит:
   на Фатихе каждый вариант оставляет 2 подтверждения вместо 7, на 55 — 0
   вместо 2. Причина — длительность меняется внутри записи, одной настройкой
   для всей суры это не описать (`madd2-local.*`, `madd6-local.*`).
2. Прототип duration-neutral сворачивает только соседние одинаковые long-vowel
   токены `ا/ۦ/ۥ/ـ` и сохраняет каждый исходный индекс/score. Качество группы —
   минимум всех исходных scores. Согласные, краткие гласные и удвоенная `ي`
   не удаляются. Raw CTC posterior отключён для этого прототипа: его вероятность
   нельзя переименовать в вероятность нормализованного алфавита. Канонический
   word identity floor и общий валидатор сохранены.
3. Статически совпали 22 из 24 сравнений нормализованных mappings 2/6 с 4.
   Исключение — 55:17 `ٱلۡمَغۡرِبَيۡنِ`: штатный phonetizer меняет число обычных
   `ي`, не отдельного ya-madd токена. Нельзя сворачивать любую `ي`: например,
   удвоенная согласная в `لِأَيِّ` является частью различимости. Это требует
   контекстных вариантов с происхождением, а не расширения глобального collapse.
4. Свежий полный согласованный список 1/32/55/59/65/73/77/80/98/112/2 плюс 79:
   12 случаев, 607 аятов, 492 фактических локальных вызова. Подтверждений
   115→162: добавлены 49, потеряны 2 (77:12/13). Новых подтверждённых ошибок
   >500 мс нет; прежняя 79:26 +508 мс остаётся. Поэтому все 162 нельзя объявлять
   правильными. Для подтверждения отсутствия прочих ошибок используется
   имеющаяся reference БД, человеческое прослушивание не заявляется.

## Регрессия 77 и второй причинный эксперимент

77:12 потерян не из-за новых фонем. Нормализация использовалась также для
весов темпа, forecast изменился 35504→35783 мс. Wasl crop стал
33282,78–38782,78 вместо 33020–38504,08 и обрезал необходимый предыдущий
контекст. После отказа 12 алгоритм остановился, поэтому потерян и 13.
Изолированный raw-tempo прототип разделяет lexical units для доказательства
и прежние raw duration-bearing units для прогнозирования окна.

Этот эксперимент сначала отклонён строгим валидатором на 55:25:
`onset_proof_mismatch`. Повтор с capture сохранил 97 reads и отвергнутые
доказательства (`raw-tempo-rejected-proof.json`, `onset-mismatch-analysis.json`).
Причина точно установлена: start запрошен 129755,335775 мс, реально прочитанный
sample start 129755,3125. Относительная позиция 2248,175182 мс, поэтому
алгоритм получил 132004, валидатор 132003 мс. Это ошибка расчёта абсолютного
времени, не ошибка модели и не повод ослаблять валидатор. Новый изолированный
sampled-onset вариант считает от `reads.calls[last_read_id].window_ms[0]`.
Свежий парный прогон 1/55/77: 135 аятов, 205 вызовов, подтверждения
22→73, прежних потерь нет, новых подтверждённых ошибок >500 мс нет.
Фатиха 7→7, сура 55 2→29, сура 77 13→37; обе потерянные границы 77:12/13
восстановлены. 55:25 теперь 132003 мс и проходит прежний валидатор.
Максимальное покрытие 57,37%, input ratio 96,58%, чтение до 6 с.
Это всё ещё более дорогой прототип: поиск 32,32→92,27 с.
`sampled-onset-local-comparison.json` содержит все добавления/потери и ограничения;
`77-window-cause.json` — доказательства связи потерь с сдвигом окна.
Полный свежий повтор на 12 сурах: 607 аятов, 579 локальных вызовов,
подтверждения 115→194, добавлено 79, прежних потерь нет. Новых подтверждённых
ошибок >500 мс нет, прежняя 79:26 +508 мс остаётся. Максимальное покрытие
57,37%, input ratio 96,58%, max read 6 с. Поиск 196,13→292,34 с,
inference в trace 148,38→243,52 с: ускорение по-прежнему не получено.
Артефакты: `sampled-onset-corpus.json/.summary.json/.log`,
`sampled-onset-corpus-comparison.json`, source zip + SHA manifest.

## Контроли и неудачи

- `derived-controls.json` — пересчёт нормализации над уже сохранённым реальным
  локальным контролем. Original/shift target совпадает, wrong target и silence
  не совпадают, group score равен min raw. Это не новый inference-контроль.
- Первый madd2 helper записал два mapping-файла в прежний audit folder.
  Variant2 копии сохранены здесь; прежние variant4 восстановлены из точно
  совпавшей статической таблицы. Raw results/controls не перезаписаны.
  Добавлен `MUA_AUDIT_DIR`, у следующих попыток отдельные audit directories.
- Первая raw-tempo команда ошибочно использовала worker Python без
  imageio-ffmpeg. Ошибка до inference сохранена в runtime-failure.log;
  повтор запущен проектной `.venv` с прежним отдельным model worker.
- Патч sampled-onset сначала ожидал одну строку, но обнаружил две, assertion
  остановил правку. Автоматически начавшийся непатченный прогон отменён;
  его лог сохранён отдельно. Затем исправлены все три места расчёта onset
  в изолированном источнике и запущена новая попытка.

В production перенесён только исправленный расчёт абсолютного onset в трёх
местах shared executor, версия sparse-9. Валидатор, пороги, бюджеты, веса темпа
и представление текста в production не менялись. Подготовлен регрессионный
end-to-end тест `tests/test_fast_sampled_onset.py` с дробным crop и пересечением
границы округления; он ещё не запускался по требованию пользователя.
Muaalem адаптер, normalization/raw-tempo, canonical floor и native edge extension
остаются прототипами. Остались причины остановки 32/2
(длинные названия букв), 65, различимость повторяющихся фраз и 79:26.
Дальше — парный контроль raw-tempo/sample-onset, затем весь список и сравнение
с поддерживаемыми моделями перед переносом общих изменений.
