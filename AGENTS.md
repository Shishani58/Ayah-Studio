# CLAUDE.md / AGENTS.md — политика AI-ассистента

Канонические правила для AI-ассистентов в этом репозитории. `CLAUDE.md` и
`AGENTS.md` — это **один документ под двумя именами**, держать их побайтово
идентичными. `CLAUDE.md` автоматически грузится в контекст; `AGENTS.md` читают
другие инструменты.

## File Sync (обязательно)

- Правишь один файл → в том же изменении правишь второй. Если разошлись —
  привести к идентичным прежде всего остального.

## Что это за проект

Desktop-инструмент (Python, pywebview + FastAPI) для генерации пер-аятных тайм-кодов аудио
Корана и их визуально-слуховой проверки. Ядро — `forced alignment` известного
текста к аудио (не транскрибация). Выход — SQLite со схемой
`timings(sura, ayah, time)` (миллисекунды) + `db_version`. Подробности — `docs/project.md`.

## Non-Negotiables

- **Корректность Корана превыше всего:** текст аятов, их число и порядок,
  тайм-коды. Никаких «правок» текста; число аятов суры берётся из
  `data/quran_mushaf.db`. Выходная БД — ровно 6236 аятов, 114 сур.
- **Воспроизводимость:** результат должен пересобираться пайплайном с
  зафиксированными флагами (модель, режим). Сгенерированные `.db` руками не
  правим в обход кода — только через экран ревью, который пишет в `review_meta`.
- **Не затирать ручную разметку:** перегенерация трогает только аяты со
  `status = auto`; `edited`/`verified` неприкосновенны.
- Трогать только то, что требует задача. Без попутных рефакторингов,
  переформатирования и спекулятивных абстракций.
- Не коммитить, не пушить, не менять формат данных без явного указания.
- Не угадывать. Читать код и доки, проверять на практике, помечать непроверенное.

## Стек и инструменты

- Python ≥3.10. Основной GUI — pywebview + FastAPI + HTML/JS;
  прежний PySide6 + pyqtgraph доступен через extra `qt`. Аудио-декод — bundled ffmpeg
  (`imageio-ffmpeg`). Рантайм выравнивания — `onnxruntime` (int8) +
  вендоренный CTC Viterbi (`core/_ctc.py`); VAD — Silero (ONNX).
  Torch — только dev-экспорт/оракул (`[align]`, алиас `[oracle]`).
- Зависимости и точки входа — `pyproject.toml`. Линтер/тесты: `ruff`, `pytest`.
- Запуск GUI: `surah-cutter-gui`. CLI-батч: `surah-cutter`.

## Минимализм

Перед новым кодом/зависимостью остановись на первом работающем шаге:
нужно ли вообще (YAGNI) → stdlib/numpy → уже установленная зависимость →
одна строка/малая правка → иначе минимум, который работает.

## Docs Routing

- Читать только доки по задаче. `docs/project.md` — точка входа перед
  изменением архитектуры, пайплайна, формата БД. `docs/STATUS.md` — что сделано
  и что осталось; обновлять при завершении работы.

## Task Files

Перед первой правкой кода для нетривиальной задачи создать
`docs/tasks/YYYY-MM-DD-короткий-слаг/task.md`: цель/скоуп, прочитанные доки и
почему, решения, чек-лист, проверка, блокеры. Это запись решений, не транскрипт.

## Документирование

- Держать доки пропорциональными: обновлять релевантные при изменении поведения
  или пайплайна. При завершении задачи в task-файле зафиксировать
  `Docs unchanged: …` либо `Docs updated: [файлы]`.

## Git

- Ветка `main`. Коммитить только по явному указанию пользователя.
- Не коммитить: `.venv/`, `__pycache__/`, `build/`, `dist/`, `models/*.onnx`,
  пользовательские `*.db`/`*.scproj` (см. `.gitignore`).

## Общение

- Отвечать по-русски, максимально кратко — и в процессе, и в финале. Финал:
  изменённые файлы, проверка, блокеры.
- Спрашивать, когда неоднозначность реально меняет результат.
